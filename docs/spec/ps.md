# kemi 仕様: 起動中のレビューの一覧

[kemi 仕様](kemi.md) の一部。起動中のレビューを一覧にする `kemi ps`。
用語の定義は `CONTEXT.md`、成功条件と反例の書き方は [kemi 仕様](kemi.md) の冒頭にある。

結果を一文で: **`kemi ps` は起動中のレビューの id・PID・URL を出し、人は URL を見失っても
開き直せ、会話が落ちて残ったサーバーを OS の kill で止められ、エージェントは JSON で id を
引き直せる。**

主な使い手は人。エージェントも `--format json` で同じコマンドを使う。保留中のセッションの
一覧は今までどおり `kemi --resume`（[R-SESSION](session.md#r-session-セッションの保存と復元)）が
受け持ち、ps は出さない。

---

## R-PS-RUNNING 起動中の判定と対象

**要件**

- ps が出すのは起動中のレビューだけ。レビューが起動中かは、そのセッションのロックが取られて
  いるかで決める。`kemi --resume` が起動中のセッションを断るときと同じ判定で、ロックは
  プロセスが終われば OS が外す（[R-SESSION](session.md#r-session-セッションの保存と復元)）。
- ps はサーバーに問い合わせない。応答しなくなったサーバーも、プロセスが生きていれば出す。
- ps の対象はセッションのある起動中のレビュー。セッションを作れずに続いたレビュー
  （[R-AGENT-CLI](agent-channel.md#r-agent-cli-kemi-wait-と-kemi-reply) の `kemi: review` の行を
  出さないもの）は出さない。
- ps はセッションの置き場所に何も書かず、何も消さない。
- セッションの置き場所が決められないとき（unix で `XDG_STATE_HOME` も `HOME` も無いなど）は、
  理由を stderr に出して終了コード `2`。起動中のレビューが 0 件のときとは区別する。置き場所は
  決められるがまだ無い（kemi を初めて使う）ときは、0 件として終了コード `0`。

**成功条件**

- `kemi --worktree --no-open` を起動しておくと、`kemi ps --format json` にその `id` が出る。
  その kemi を SIGTERM で保留にすると、次の `kemi ps --format json` は `[]` になる（e2e）。
- 保留中のセッションがあり、起動中のレビューが無いとき、`kemi ps --format json` が `[]` で
  終了コード `0`（e2e）。
- サーバーが応答しない状態（プロセスを SIGSTOP で止める）でも、`kemi ps` が 5 秒以内に終わり、
  その `id` と PID が出る（e2e。unix のみ）。
- unix で `XDG_STATE_HOME` も `HOME` も無い環境の `kemi ps` が、stdout 空・終了コード `2`（e2e）。
- `kemi ps` の前後で、セッションの置き場所のファイルの一覧と中身が変わらない（e2e）。

**反例**

- 保留中のセッションが ps に出る。
- ps が各サーバーの応答を待って遅くなる。応答しないサーバーが一覧から消え、止める手がかりが
  無くなる。
- 置き場所が決められないのに、0 件として終了コード `0` で終わる。

## R-PS-RECORD 起動中の記録

ps が読む値を、起動中のレビューが自分で書いておくファイル。

**要件**

- 起動したレビューは、`<id>` ごとの起動中の記録を `<id>.endpoint` と同じ置き場所に書く
  （[R-AGENT-LINK](agent-channel.md#r-agent-link-つなぎ先と安全)。unix ではセッションと同じ。Windows では
  `XDG_STATE_HOME` に関わらず `%LOCALAPPDATA%\kemi\sessions\`）。ページのトークンを持つので、
  エージェントのトークンと同じ守り方にそろえる。ps はロックをセッションの置き場所から、記録を
  この置き場所から読む。Windows で `%LOCALAPPDATA%` が決められないときは記録を書けず、書けない
  ときと同じく警告を出してレビューを続ける。
  持つ値は次のとおり。
  - PID（serve している kemi のプロセス）
  - ページの URL（stderr の `kemi: <url>` と同じもの。ページのトークンを含む）
  - `--live` なら中継の URL（stderr の `kemi: live <url>` と同じもの。[R-PAGE-MODE](live.md#r-page-mode-起動)）
  - 起動した時刻（このプロセスがサーバーを起動した時刻の UTC）
  - 製品の版
  - モード（worktree / staged / コミット範囲 / manifest / `--live`）と、その表示の文字
  - ワークスペースのパスと識別（セッションの情報と同じ。[R-RESULT](output.md#r-result-結果ファイル) の基準）
- エージェント用のトークンは持たない。ps は `<id>.endpoint` を読まない
  （[R-AGENT-LINK](agent-channel.md#r-agent-link-つなぎ先と安全)）。
- 起動中の記録は、最初の `kemi: <url>` の行を stderr に出す前に、一時ファイルから名前を変える
  原子的な差し替えで書く（書きかけのファイルを ps が読まない）。権限は `<id>.endpoint` と
  同じ（unix はファイル `0600`。Windows は `%LOCALAPPDATA%\kemi\sessions\` の既定の権限）。
- submit・保留・実行時エラーで終わるときに、セッションのロックを外す前に消す（ロックを外した
  後に消すと、その間に同じ `id` を復元したレビューの記録を消しうる）。
- 強制終了で残ったものは、そのセッションのロックが外れていれば無いものとして扱い、読まない。
  掃除（[R-SESSION](session.md#r-session-セッションの保存と復元)）は、`<id>.endpoint` と同じく、ロックの
  外れた起動中の記録をセッションの有無に関わらず消す。セッションを消すときにも一緒に消す。
  セッションの大きさ（`<id>.session` と `<id>.payload` の合算）には数えない。
- `kemi --resume` で同じ `id` を続けるときは、ロックを取った後、先に古い記録を消してから、その
  復元の PID・URL・起動した時刻で書く。書けなかったときに、前のプロセスの PID が出ないように
  するため。ワークスペースは、セッションの記録した元のワークスペース（復元したディレクトリでは
  ない）。
- 起動中の記録を書けなかったときは、警告を stderr に出してレビューを続け、終了コードを
  変えない。そのレビューは ps に `id` だけで出る（[R-PS-OUTPUT](#r-ps-output-出力)）。

**成功条件**

- 起動中のレビューの起動中の記録が unix で `0600` になり、submit の後と保留の後に無い（e2e）。
- `kemi ps --format json` の `url` で `api/review` が応答する。どのキーの値にも、そのレビューの
  `<id>.endpoint` のトークンが現れない（e2e）。
- SIGKILL で止めたレビューの起動中の記録が残っていても、`kemi ps` にそのレビューが出ない。
  そのあと別のレビューを起動してセッションを書くと、残った記録が消える（e2e）。
- 保留したセッションを `kemi --resume <id> --no-open` で続けると、`kemi ps --format json` の
  `pid`・`url`・`started_at` が復元したプロセスのものになる（e2e）。
- Windows で、起動中のレビューの `kemi ps --format json` に `pid` と `url` が出る。`XDG_STATE_HOME`
  を一時ディレクトリにしても同じ（Windows の CI の cargo test）。

**反例**

- ps の出力にエージェント用のトークンが出る。
- 強制終了で残った起動中の記録のために、止まったレビューが起動中に見える。
- 起動中の記録を書けないだけで、レビューが起動できない。

## R-PS-OUTPUT 出力

**要件**

- 範囲: 引数なしでは、今のリポジトリ（[R-RESULT](output.md#r-result-結果ファイル) と同じ識別の
  基準）のレビューを出す。`--any` を付けると場所を問わず出す。復元したレビューは、セッションの
  記録した元のワークスペースで範囲に入るかを決める。起動中の記録が無い・読めないレビューは
  ワークスペースが分からないので、範囲を問わず引数なしの ps にも出し、範囲の外の数には数えない。
- 出力の形は `--format text|json` で選び、既定は `text`。`kemi wait` などが JSON を出すのと
  違い、ps の既定は人が読む `text` であることをヘルプに書く。
- 並びは起動した時刻の新しい順。時刻が取れないものは最後。時刻が同じか取れないもの同士は
  `id` の順。`--any` でもワークスペースごとにはまとめない。
- ロックは取られているのに起動中の記録が無い・読めないレビュー（この変更より前の版で起動した
  サーバー、記録を書くまでの一瞬、壊れた記録）は、`id` だけで出し、ほかの値は空にする。
  記録が読めないときは理由を stderr に警告として出し、無いときは警告しない。どちらも終了
  コードは `0`。
- 最初の引数が `ps` ならサブコマンドとして扱う。`ps` という名前の manifest を開くときは
  `kemi ./ps` と書く（`wait`・`reply`・`explain` と同じ決まり）。`--any` と `--format` 以外の
  フラグ、余分な引数、`text` と `json` 以外の `--format` の値は、理由と使い方を stderr に出して
  終了コード `2`。

### text

人が読む表。列の並びと幅、0 件の行と範囲の外の行の文面は約束しない。ほかの出力と同じく英語で
出す。

- 出す値は、`id`・モード・起動した時刻・PID・URL。`--live` のレビューでは中継の URL も出す。
  `--any` のときはワークスペースも出し、ホームディレクトリは `~` に縮める。
- 時刻は `kemi --resume` の一覧と同じローカル時刻の `YYYY-MM-DD HH:MM`。モードの文字は
  `kemi --resume` の一覧のモードの列と同じ。
- URL は切らない。
- 0 件のときは、表の代わりに起動中のレビューが無いことを 1 行で出し、終了コード `0`。
- `--any` を付けていないとき、範囲の外に起動中のレビューがあれば、表（または 0 件の行）の後に
  その数と、`--any` で出せることを 1 行添える。

### json

起動中のレビュー 1 つを 1 要素とする配列を stdout に出す。0 件なら `[]`。キーは次のとおりで、
エージェントやほかのツールが読む形として約束する。範囲の外の数は出さない。

| キー | 中身 |
|---|---|
| `id` | セッションの `id` |
| `workspace` | ワークスペースのパス |
| `mode` | `worktree` / `staged` / `range` / `manifest` / `live` のどれか |
| `label` | `kemi --resume` の一覧のモードの列と同じ文字（`from..to`、manifest の `title`、`live <URL>` など） |
| `started_at` | 起動した時刻 |
| `pid` | serve している kemi のプロセスの PID |
| `url` | ページの URL |
| `live_url` | 中継の URL。`--live` でなければ `null` |
| `version` | 起動したサーバーの製品の版 |

取れない値は `null` にし、ほかの値から推測して埋めない。時刻は RFC 3339 の UTC。起動中の記録が
無い・読めないレビューでは、`id` 以外がすべて `null` になる。ワークスペースの識別（起動中の記録が持つ、範囲の判定に使う値）は
JSON に出さない。

**成功条件**

- リポジトリ A と B でそれぞれレビューを起動し、A で `kemi ps` を打つと A のレビューだけが出て、
  B の 1 件と `--any` が最後の 1 行に出る。`kemi ps --any` では両方が出る（e2e）。
- `kemi ps` の text の出力に、起動中のレビューの PID と、stderr の `kemi: <url>` と同じ URL が
  出る。0 件でも stdout に 1 行出て、終了コード `0`（e2e。値が出ていることだけを確かめ、列の
  並びや幅は確かめない）。
- `--live` のレビューの `kemi ps --format json` で `live_url` が stderr の `kemi: live <url>` と
  同じになり、`--live` でないレビューでは `null`（e2e）。
- 2 つのレビューを順に起動すると、`kemi ps --format json` で後に起動した方が先に並ぶ（e2e）。
- 別のリポジトリで起動して起動中の記録を消したレビューと、壊したレビューがあるとき、引数なしの
  `kemi ps --format json` は終了コード `0` で両方の `id` を出し、ほかのキーは `null`。stderr の
  警告は壊した方だけに出る（e2e）。
- `kemi ps --all` と `kemi ps extra` が終了コード `2`（e2e）。
- `kemi ./ps` が `ps` という名前の manifest を開く（e2e）。

**反例**

- URL が途中で切れて開けない。
- 0 件のとき何も出ず、起動中のレビューが無いのか壊れたのか区別できない。
- 1 つのレビューの記録が壊れているだけで、ps が失敗し、残ったサーバーを探せない。
- 既定の範囲の外に残ったサーバーがあるのに、text が何も知らせずに終わる。
- 取れない値を、ほかの値から推測して埋める。

## R-PS-STOP 止め方

**要件**

- ps で見つけたレビューは、人が ps の出した PID に OS の kill を送って止める。止めるための
  kemi のコマンドは作らない。
- unix では SIGTERM で保留として終わり（終了コード 130。[R-SESSION](session.md#r-session-セッションの保存と復元)）、
  復元できるセッションが残るときは `kemi --resume <id>` で続けられる。SIGTERM で止まらない
  サーバーは SIGKILL で止めてよく、そのときも、最後に書けたところに復元できるセッションが
  あれば `kemi --resume <id>` で続けられる。どちらも、ページを一度も開かず写しができる前に
  止めたレビューは、R-SESSION のとおりセッションを残さない。
- Windows では SIGTERM が無く、別のプロセスから止めるのは `taskkill /F /PID <pid>` などの強制
  終了になる。保留の行は出ないが、SIGKILL と同じ条件で `kemi --resume <id>` で続けられる。
  README にそう書く。
- スキル（`skills/kemi/SKILL.md`）に、エージェントが `id` を見失ったとき `kemi ps --format json`
  で引き直す手順を書く。

**成功条件**

- ページの `api/review` を取って写しができたレビューに、`kemi ps` が出した PID で SIGTERM を
  送ると、終了コード 130 で終わり、引数なしの `kemi ps` から消え、`kemi --resume <id>` で始まる
  （e2e。unix のみ）。
- 同じ条件で SIGKILL で止めたときも、`kemi --resume <id>` で始まる（e2e。unix のみ）。
- README の Windows の止め方の記述と、スキルの手順（差分のレビューで確かめる）。

**反例**

- kill で止めたあと、残ったロックや起動中の記録のために同じセッションを復元できない。

## 作らないもの

- P27 ps の `-a`（保留中のセッションも出すこと）。保留中のセッションの一覧は `kemi --resume`
  が受け持つ。
- P28 `kemi stop` などの止めるコマンドと、ps から選んで止める対話の画面。
- P29 ps が各サーバーに問い合わせること（応答の有無やエージェントの状態を出すこと）。
- P30 セッションを作れずに続いたレビューを ps に出すこと。

## 委譲

- D17 起動中の記録のファイル名と中身の形。どの形でも `R-PS-RECORD` の値・寿命・権限と、
  `R-PS-OUTPUT` の JSON の契約は同じ。
- D18 text の表の列の並びと幅、0 件の行と範囲の外の行の文面。text は見た目を約束しない。

## 却下

- R28 ps の `-a` で保留中のセッションも出す（理由: 保留中のセッションの一覧を ps と
  `kemi --resume` の 2 か所で約束することになり、片方だけ直すズレが起きる）。
- R29 ps に一覧を寄せ、`kemi --resume` の端末でないときの一覧をやめる（理由:
  `R-SESSION` の契約を壊す）。
- R30 記録した PID の生死で起動中を決める（理由: PID の使い回しで誤り、`kemi --resume` の
  判定とずれうる）。
- R31 各サーバーに HTTP で問い合わせて起動中を決める（理由: 待ち時間の上限が要り、応答しない
  サーバーが一覧から消える）。
- R32 どこで打っても全部の範囲を出す（理由: `kemi --result` の「今のリポジトリが既定」と
  そろわない）。
- R33 出力を text だけにする（理由: エージェントが `id` を見失ったときに取り戻せない）。
  JSON だけにする（理由: 主な使い手は人）。
- R34 起動中の値を `<id>.endpoint` に足す（理由: エージェント用の API が立たないレビューが ps に
  出ず、ps がエージェントのトークンと同じファイルを読む）。
- R35 起動中の値を `<id>.lock` の中身に書く（理由: Windows ではロック中のファイルをほかの
  プロセスが読めない）。
- R36 ページの URL を置かずポートだけを出す（理由: URL を取り戻す目的が果たせない）。
- R37 text に見た数 / 全数も出す（理由: 起動したばかりで状態が無いレビューの扱いと、状態を書く
  たびの記録の書き直しが要る）。
- R38 セッションの無いレビューのために別の置き場所を作る（理由: 置き場所の決め方が 2 つになり、
  ロックの無いレビューの判定を別に作る必要がある）。
- R39 JSON から `version` を外す（理由: kemi を上げたあと古い版のまま残ったサーバーを
  見分けられない）。`mode` を `kemi --resume` のモードの文字 1 つにまとめる（理由: 機械が種類で
  分けるのに文字を読み解く必要がある）。
- R40 記録の無い起動中のレビューを出さない（理由: 古い版で残ったサーバーに気づけない）。
- R41 ps がロックの外れた起動中の記録を消す（理由: 一覧を出すだけのコマンドがファイルを
  消すことになる）。
- R42 ps を unix だけにする（理由: Windows で URL を見失うと取り戻せない）。
- R43 セッションの置き場所が決められないとき 0 件として出す（理由: 置き場所の設定が壊れて
  いることに気づけない）。
- R44 起動中の記録を書けなければ起動を失敗させる（理由: 補助のファイルが書けないだけで
  レビューができなくなる）。
- R45 起動中の記録が無い・読めないレビューを範囲の外として扱い、`--any` のときだけ出す（理由:
  古い版で残った、止めたい代表の相手が既定の一覧から隠れる）。`<id>.session` のワークスペースで
  範囲を決める（理由: ps が読む場所が 2 つになり、起動したばかりのレビューには `<id>.session` が
  無い）。
- R46 Windows で `XDG_STATE_HOME` があるとき、起動中の記録をロックと同じセッションの置き場所に
  置く（理由: `XDG_STATE_HOME` を持ち主以外も読める場所に向けると、ページのトークンがその権限で
  置かれる。トークンを持つファイルの置き場所の決まりを `<id>.endpoint` の 1 つにそろえた）。

## 未決

- Windows で `XDG_STATE_HOME` を設定したとき、`<id>.endpoint` の置き場所（`%LOCALAPPDATA%` 側）を
  掃除とセッションの削除が見ず、ロックの外れた endpoint が消えずに残る可能性がある（今の実装を
  読んだ見立てで、動かしては確かめていない）。起動中の記録も同じ置き場所なので同じ問題を受け継ぐ。
  確かめて直すかは、ps とは別の作業として人が決める。
