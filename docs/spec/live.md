# 動いているページのレビュー 仕様

- Status: 草稿（ライブ改訂）
- 用語の定義: `CONTEXT.md`
- 本体の仕様: [kemi 仕様](kemi.md)。エージェントとの往復は [agent-channel.md](agent-channel.md)
- 比べる相手（スナップショットとモックの選び方、重ねて透かす表示）: [live-compare.md](live-compare.md)

結果を一文で: **手元の開発サーバで動いているページか手元の HTML ファイルを kemi の中に出し、
要素・矢印・ペンでコメントを付け、エージェントが直した結果をスナップショットやモックと見比べて
確かめ、見た目の案をその場で切り替えて選べるようにする。**

見る対象は、ループバックの URL で動いているページ（Storybook などのコンポーネントの画面を含む）と、
手元の HTML ファイル。どちらも以下では「ページ」と呼ぶ。画像（デザイン画像やエージェントが撮った
スクリーンショット）を見る対象・比べる相手にすることは、後の別の仕様で足す（[作らないもの](#作らないもの)）。

各要件の「成功条件」と「反例」の書き方は [kemi 仕様](kemi.md) の冒頭と同じ。証拠の出所は
[R-VERIFY](kemi.md#r-verify-検証)。

画面の配置・見た目・道具の出し方は、試作を重ねて決める。見た目の参照は
`docs/design/ui-mock-live.html`（採用した画面モック。案 A）。画面モックとこの仕様が食い違うときは
仕様が正しい。この仕様が決めるのは、見え方が変わっても守る約束だけ。

## R-PAGE-MODE 起動

**要件**

- `kemi --live <URL>` か `kemi --live <ファイル>` で起動する。
  - `<URL>` は `http://` で、ホストがループバック（`localhost` か `127.0.0.0/8`）のものだけを
    受け付ける。
  - `<ファイル>` は、配れる範囲（下）の中にある `.html` か `.htm` だけを受け付ける。kemi は
    配れる範囲の中のファイルを配る。配れる範囲の中のファイル（見ている HTML と、それが参照する
    CSS・画像などを含む）が保存されたら、ページを読み込み直す。配れる範囲の中の別の HTML への
    リンクで移るのは、ページの移動として扱う。
  - 配れる範囲: kemi を起動したディレクトリが git の作業ツリーの中なら作業ツリーの根の下、
    そうでなければ起動したディレクトリの下。シンボリックリンクは実体の場所で判定する。`.git/` の
    中は配らない。git が無視するファイル（`.gitignore`）も範囲の中なら配る。
  - それ以外は使い方の誤りとして終了コード 2。
- 組めるフラグは `--port`・`--bind`・`--no-open`・`--live-port <n>`・`--focus`・`--serve`（互換のための受理だけ）。ほかの入力
  モード、`--digest`、`--result` と組んだら使い方の誤りとして終了コード 2。`--live` の
  セッションは `--resume <id>` で再開できる（[R-PAGE-SESSION](#r-page-session-保留と復元)）。
- レビューは「ページ」と「コード」の 2 つの見方を持つ。
  - ページ: 動いているページと比べる相手を並べる（[R-PAGE-VIEW](#r-page-view-ページの見方)、
    [比べる相手](live-compare.md#r-page-ref-比べる相手)）。
  - コード: 作業ツリーの差分。`--worktree` と同じグループ・同じ表示
    （[R-INPUT](kemi.md#r-input-入力)）。
- 起動したときに開発サーバにつながらなくても、起動は止めない。ページの見方につながらないことを出して
  待ち、つながったらページを出す（復元したときと同じ。[R-PAGE-SESSION](#r-page-session-保留と復元)）。
- git リポジトリの外で起動したら、コードの見方を出さず「git リポジトリではないので
  コードの差分は出せない」と出す。ページへのコメント・案・submit はできる。
- 起動時に stderr へ `kemi: live <url>`（中継の URL）の 1 行を出す。`kemi: <url>`
  （[R-INPUT-6](kemi.md#r-input-6-その他の入出力)）と `kemi: review <id>`
  （[R-AGENT-CLI](agent-channel.md#r-agent-cli-kemi-wait-と-kemi-reply)）も出す。この 3 行は契約とする。
  順は `kemi: <url>` → 公開時の警告 → 結果の保存先 → `kemi: review <id>` → `kemi: live <url>`。
  `<ファイル>` で起動したときも `kemi: live <url>` を出す（kemi が配るページの URL）。
- `<ファイル>` で起動したレビューでは、ページの URL のパスは配れる範囲の根からの相対パスになる
  （例: `/docs/design/mock.html`）。画面の題、復元の一覧のモードの列、submit の JSON の
  `page.url`（[R-SUBMIT](kemi.md#r-submit-送信と契約)）は、この URL を使う。
- 承認が承認するのはコードの変更（作業ツリーの差分）。git リポジトリの外ではページを見ての
  判断だけになる。どちらの場合も `approval` は `[]`（manifest が無いので、worktree と同じ）。
- `--live` を使わないレビューでは、ページ用の機能（中継、スナップショット、案）を読み込まない。
  今のモードの性能の約束（[R-SERVE](kemi.md#r-serve-配信モデル) と [R-VERIFY](kemi.md#r-verify-検証)）は変えない。

**成功条件**

- `kemi --live http://example.com/`、`kemi --live https://localhost:5173/`、
  `kemi --live http://localhost:5173/ --worktree`、`kemi --live http://localhost:5173/ --digest`、
  配れる範囲の外の HTML ファイル、配れる範囲の中の `.txt` ファイル、配れる範囲の外を指す
  シンボリックリンクを渡すと、それぞれ終了コード 2（e2e）。
- 作業ツリーの中の HTML ファイルを渡すと、stderr に 3 行が出てページが読め、そのページが参照する
  CSS を保存し直すとページが読み込み直される（e2e とブラウザ自動化）。
- git リポジトリの外の起動したディレクトリの下にある HTML ファイルを渡すと、ページが読める（e2e）。
- ファイルのページの中で配れる範囲の別の HTML へのリンクを押すと、見る対象がその HTML に移り、
  ページのツリーにそのページが出る（ブラウザ自動化）。
- 試験用の開発サーバで `kemi --live http://127.0.0.1:<port>/ --no-open` を起動すると、
  stderr に 3 行が出て、`kemi: live <url>` の URL からページが読める（e2e）。
- git リポジトリの外で起動すると、コードの見方の代わりに理由が出る（ブラウザ自動化）。
- 開発サーバを止めたまま起動すると、つながらない旨が出て、開発サーバを起動するとページが出る
  （ブラウザ自動化）。

**反例**

- 外のサイトを指定でき、kemi が他人のページにスクリプトを差し込む。

## R-PAGE-PROXY 中継と安全

**要件**

- kemi はレビュー画面とは別のポートで `<URL>` のオリジンを中継し、ページとして開かれる HTML の応答に
  ページ用のスクリプト（要素の選択、描き込み、スナップショット、案の差し替え）を差し込む。ページとして
  開かれるとは、文書としての移動か iframe への読み込みのこと。ページのスクリプトが取りに来た HTML
  （fetch などで取る HTML のかけら）には差し込まず、そのまま返す。
- 中継する HTML の応答は 32 MB まで。超えるものは中継せず、超えたことをページに出す。
  中継のポートは既定で空きを選び、`--live-port <n>` で固定できる。`<ファイル>` で起動したときは、
  同じポートでそのファイルと同じ範囲のファイルを配り、HTML に同じスクリプトを差し込む。この節の
  ほかの約束（別のオリジン、cookie、`--bind`）もそのまま効く。
- 中継したページはレビュー画面と別のオリジンで動き、レビュー画面とは `postMessage` だけで
  話す。開発中のページのスクリプトは kemi の API に届かない。
- `--bind` はレビュー画面と中継の両方に効く（[R-SERVE](kemi.md#r-serve-配信モデル)）。
  公開時の警告に、URL を知る人は開発中のページも見られることを足す。
- 中継のポートは中継用の cookie を持つ要求だけを通す。cookie の値はページのトークンとは別の
  中継用の値で、トークンの URL（`/s/<token>/`）を開いたときに入れ、`HttpOnly` と
  `SameSite=Strict` を付ける。開発サーバへ転送する前に、この cookie を要求から取り除く。kemi の
  API は今までどおりパスのトークンと `Origin`・`Host` の検証（[R-SERVE](kemi.md#r-serve-配信モデル)）で受け付け、
  cookie では受け付けない。
- WebSocket（開発サーバの HMR など）は中身を解釈せず、バイト列をそのまま中継する。
- 応答の `X-Frame-Options` を外し、CSP の `frame-ancestors` をレビュー画面のオリジンだけに
  書き換え、`script-src` に差し込むスクリプトだけを足す。ほかの CSP は変えない。書き換えた
  ときは、画面に書き換えたことを小さく出す。
- 依存は [R-DEPS](kemi.md#r-deps-依存) に従う（C 依存を足さない、許可したライセンスだけ）。

**成功条件**

- 試験用の開発サーバで、ファイルを書き換えると HMR で中継したページが変わる
  （ブラウザ自動化）。
- cookie を持たない要求が中継のポートで拒否される。cookie が `HttpOnly` で、中継した
  ページの `document.cookie` に出ない（統合テストとブラウザ自動化）。
- `X-Frame-Options: DENY` と `frame-ancestors 'none'` を返す試験用サーバのページが、
  レビュー画面の中に出て、書き換えの表示が出る（ブラウザ自動化）。
- `--bind 0.0.0.0` の警告に、開発中のページも見られることが入る（e2e）。
- ページのスクリプトが fetch で取りに来た HTML には、ページ用のスクリプトが差し込まれない
  （統合テスト）。

**反例**

- 中継したページの JS がトークンを読み、kemi の API を呼ぶ。
- 中継のポートが、トークンを知らない LAN の端末に開発中のページを見せる。

## R-PAGE-VIEW ページの見方

**要件**

- 動いているページと比べる相手（[R-PAGE-REF](live-compare.md#r-page-ref-比べる相手)）を、
  同じ表示幅で並べる。画面に収まらないときは両方に同じ倍率をかけて縮める。
- 表示幅を選べる。既定の候補は 390・768・1280 と、任意の数字（320〜3840）。範囲の外の数字は
  受け付けず、範囲を画面に出す。
- 動いているページは HMR やファイルの保存でその場で変わってよい（[R-LIVE](kemi.md#r-live-ライブリロード) の
  「勝手に表示を変えない」の例外）。コードの見方は今どおり更新バッジを押して読み直す。
- ページの中で別の URL に移ってよい。比べる相手がスナップショットのときは、今の URL（パスと
  クエリ。`#` から後ろは無視）と表示幅が同じスナップショットだけを使う。モックの割り当ても
  その幅のスナップショットも無ければ「このページ・この幅の前は記録されていない」と出し、
  その場で取る操作を置く。
- 比べる相手がスナップショットのときは、並べるだけにせず、変わったところに必ず印を付け、
  変化の一覧を出す（[R-PAGE-DIFF](#r-page-diff-差分)）。[R25](kemi.md#却下) の「変更点を目で探す」には
  当たらない。モックと比べるときの見比べ方は [live-compare.md](live-compare.md#r-page-ref-比べる相手)。
- ページの見方の左の列は、ページのツリー。スナップショット・コメント・モックの割り当てのいずれかが
  あるページと、表示中のページを並べる。各ページに、スナップショットを取った表示幅とコメントの
  数を出す。モックを割り当てたページにはそのことを出す。ページを押すと見る対象をその URL に移し、
  表示幅を押すとその幅にも切り替える。表示中のページの比べる相手がスナップショットのときは、
  その下に今の表示幅での変化の一覧（[R-PAGE-DIFF](#r-page-diff-差分)）と変化の数を出す。表示中で
  ないページの変化の数は出さない（計算していないため）。コードの見方では、左の列は今どおり
  ファイルのツリー（[R-VIEW](kemi.md#r-view-差分の表示)）。
- 狭い画面（[R-NARROW](kemi.md#r-narrow-狭い画面)）では、動いているページと比べる相手を
  1 枚ずつ切り替えて見る。ペンと矢印は指で描け、要素はタップで選べる。ツリーは引き出しに、会話パネルは
  シートにしまう。比べる相手の選択と重ねて透かす表示（[R-PAGE-REF](live-compare.md#r-page-ref-比べる相手)）は
  狭い画面でも使える。

**成功条件**

- スナップショットを持つページを 2 つ見た後、ページのツリーに 2 つのページとその表示幅が並び、
  もう一方のページを押すと見る対象がその URL に移る（ブラウザ自動化）。
- コメントだけがあるページと、モックの割り当てだけがあるページが、ページのツリーに出る。
  表示幅の札を押すと、そのページのその幅に切り替わる（ブラウザ自動化）。
- 表示幅 390 と 1280 のそれぞれでスナップショットを取ってから幅を切り替えると、動いている
  ページと比べる相手が同じ幅で描かれる。スナップショットの無い幅に切り替えると、記録されて
  いない旨と取る操作が出る（ブラウザ自動化）。
- 別の URL に移ると、その URL のスナップショットが無い旨が出る（ブラウザ自動化）。
- 表示幅に 319 と 3841 を入れると受け付けられず、範囲が出る（ブラウザ自動化）。
- 幅 390px のブラウザで開くと、1 枚ずつの表示と切り替えが出る（ブラウザ自動化。指での
  操作感は人による確認）。

**反例**

- 比べる相手と動いているページが違う幅で描かれ、縮尺がずれる。

## R-PAGE-SNAPSHOT スナップショット

**要件**

- スナップショットは、動いているページのある時点の DOM と CSS（shadow DOM・canvas の
  中身・入力欄の値を含む）を記録したもので、スクリプトを含まない。URL と表示幅を覚える。
- 取る時点: レビューの開始時（開始時に開発サーバにつながらなければ、最初につながったとき）と、
  「エージェントに渡す」のたび（表示中のページだけ）。
  手で取る操作もある。どのスナップショットを比べる相手にするかは
  [R-PAGE-REF](live-compare.md#r-page-ref-比べる相手)。
- スナップショットはレビュー画面の中で、スクリプトを止めた `sandbox` 付きの iframe に出す。
- 1 つ 2 MB まで。超えるものは取らず、取れなかったことを画面に出す。比べる相手は 1 つ前の
  スナップショットのまま。

**成功条件**

- shadow DOM・canvas・SVG・入力欄を持つ試験用ページのスナップショットが、動いている
  ページと同じ見た目で出る（ブラウザ自動化で画素を比べる。完全一致でなくてよい差は人に
  よる確認）。
- `onclick` 属性を持つ要素を含むスナップショットで、押してもスクリプトが動かない
  （ブラウザ自動化）。

**反例**

- スナップショットの中のスクリプトがレビュー画面のオリジンで動く。

## R-PAGE-DIFF 差分

**要件**

- 比べる相手がスナップショットのとき、比べる相手と動いているページを要素ごとに対応させ、
  変化を 2 種類に分けて出す（モックのときは出さない。[比べる相手](live-compare.md#r-page-ref-比べる相手)）。
  - 主な変化: 見た目（色・文字の大きさ・角丸など）、文字、要素が増えた・消えた。
  - ずれただけ: 位置と大きさだけが変わったもの。既定では一覧で畳み、印も控えめにする。
- 要素の対応づけは次を守る（方法は DL2）。
  - 兄弟の途中に 1 つ要素が入る・消えるとき、その後ろの要素は増えた・消えたにならず、
    ずれただけに入る。
  - 要素に `id` があればそれで対応させる。
- 主とずれの線引きの細部（空白だけの文字の差を無視するかなど）は試作で決める。

**成功条件**

- 兄弟の途中に要素を 1 つ足すと、足した要素だけが増えたになり、後ろの要素は増えた・消えた
  にならない（ブラウザ自動化）。
- ボタンの背景色を変えると、そのボタンが主な変化に入り、色の前後の値が出る（ブラウザ自動化）。

**反例**

- 1 つの要素が大きくなっただけで、下にある要素がすべて主な変化に並ぶ。

## R-PAGE-COMMENT コメントの場所

**要件**

- ページへのコメントの場所は 3 種類: 要素（選んだ要素）、矢印、ペン（囲んだ線）。場所は見る対象の
  側にだけ置ける（比べる相手の側には置けない）。
  1 つのコメントは場所を 1 つ以上持て、場所にはそのコメントの中で 1 から番号を振る。本文は
  番号で場所を指せる。コメントは URL と表示幅を覚える。
- エージェントに渡すもの:
  - 要素: セレクタ、文字、位置と大きさ。
  - 矢印: 矢印の点と、先にある要素（要素と同じ情報）。
  - ペン: 線の点と、囲んだ範囲と重なる要素（重なる面積の大きい順に 5 個まで）。
  - コメントごとに、場所の周りに描き込みと番号を重ねた画像のファイル。セッションの置き場所の
    `<id>.files/` に置き、絶対パスで渡す（[R-PAGE-SESSION](#r-page-session-保留と復元)）。
- 別の表示幅で付けたコメントには、付けた幅を出し、押すとその幅に切り替わる。
- 書いている途中は場所を足し、取り消せる: 一覧からの削除、同じ要素をもう一度選んで外す、
  最後の 1 つの取り消し、描いている途中の取りやめ。番号は消しても振り直さない（本文が番号で
  指しているため）。保存した後は場所を変えない。変えたいときは削除して付け直す
  （[R-COMMENT](kemi.md#r-comment-コメントと-suggestion) の行レンジと同じ）。
- submit の JSON での形は [R-SUBMIT](kemi.md#r-submit-送信と契約) の `page`。

**成功条件**

- 要素・矢印・ペンの 3 つの場所を持つコメントを付けて渡すと、`kemi wait` の JSON に番号 1〜3 の
  場所と、それぞれの種類と要素の情報、画像のファイルの絶対パスが入り、そのファイルが読める（e2e）。
- 2 番目の場所を消してから保存すると、場所の番号が 1 と 3 のまま残る（ブラウザ自動化）。
- 矢印の先の要素が、矢印の先端の位置にある要素と一致する（ブラウザ自動化）。

**反例**

- 矢印とペンが座標だけで渡り、エージェントがどこを指しているか分からない。
- 間違えて選んだ要素を外せない。

## R-PAGE-VARIANT 案

**要件**

- 案は「セレクタで選んだ要素を HTML に置き換える」と「ページに足す CSS」の組み合わせ。
  1 つの案で置き換えは 8 か所まで。エージェントが返信に付ける
  （[R-AGENT-WRITE](agent-channel.md#r-agent-write-reply-の入力と上限)）。
- 案はスレッドの下に並び、選ぶと動いているページの上でその場で差し替わる。kemi は
  ファイルに書かない。元に戻すこともできる。
- 案を並べて見られる。すべての案（元を含む）を、対象の周りごと同じ縮尺で並べる。
- 読み込み直しや HMR で差し替えが消えたら掛け直す。
- 「これにする」は、エージェントに渡る起きたことの 1 つ（`chosen`）
  （[R-AGENT-EVENTS](agent-channel.md#r-agent-events-wait-が返す-json)）。
- エージェントが返信の `applied` で反映を知らせたら、その案の差し替えをやめ、本物のページを
  見せる。
- ふるまいを含む案（押すと開くメニューなど）は案の仕組みで扱わない。エージェントがコードで
  作り、普通の往復で見せる。

**成功条件**

- 3 つの案を持つ返信で、案を切り替えるとページの対象が差し替わり、元に戻せる。ページを
  読み込み直しても選んだ案が残る（ブラウザ自動化）。
- 並べて見ると、元と 3 つの案が同じ縮尺で出る（ブラウザ自動化）。
- `applied` を受けると、差し替えが外れる（ブラウザ自動化）。

**反例**

- 案を選ぶと kemi が作業ツリーのファイルを書き換える。
- 反映の後も差し替えが残り、本物と案が重なって見える。

## R-PAGE-SESSION 保留と復元

**要件**

- `--live` のセッションは写しを持たない（動いているページは止めておけない）。
  [R-SESSION](kemi.md#r-session-セッションの保存と復元) の「元の入力を読み直さない」
  （[R21](kemi.md#却下)）の例外。
- 保存するもの: コメント・返信・発言・案・解決と折りたたみ・モックの割り当て（`<id>.session`）、
  スナップショットと描き込みの画像（`<id>.files/`）。
- `<id>.files/` は 1 セッション 20 MB まで。超えそうなら、古い渡した時点のスナップショット →
  古い手で取ったスナップショット → 削除したコメントの画像、の順に消す。開始時のスナップショットは
  消さない。それでも超えるなら新しいものを保存せず、保存しなかったことを画面に出す。
  submit を確定したら `<id>.session` と一緒に消す。
- コメント・返信・発言が 1 つも無い `--live` のセッションは、保留しても残さない。
- 復元すると同じ `<URL>` につなぎ直す（`<ファイル>` のときは同じファイルを配り直す）。
  つながらない・ファイルが無いときは、そのことをページに出して待つ。コードの見方は復元時の作業ツリーを読み、監視と更新バッジも続ける
  （[R-LIVE](kemi.md#r-live-ライブリロード) の例外）。
- 復元の一覧と選択の画面に `--live` のセッションも出る。モードの列は `live` と URL。

**成功条件**

- `--live` で保留して復元すると、コメント・返信・案とスナップショットが戻る（e2e と
  ブラウザ自動化）。
- 開発サーバを止めたまま復元すると、つながらない旨が出て、開発サーバを起動するとつながる
  （ブラウザ自動化）。

**反例**

- 復元すると、レビュー開始時のスナップショットが消えている。

## 作らないもの

- PL1 ループバック以外（LAN のサーバ、公開中のサイト、`https://`）の中継。そうしたページの確認は、
  エージェントが撮ったスクリーンショットに描き込む形で、後の画像の仕様で扱う（PL4）。
- PL2 kemi が撮るスクリーンショットで、スナップショットの代わりに前後を比べること（デザイン画像や
  エージェントが撮った画像を比べる相手にするのは PL4）。
- PL3 kemi がブラウザを操作する仕組み（CDP など）。
- PL4 画像を見る対象にすること（画像への描き込み）と、デザイン画像を比べる相手にすること。
  エージェントが撮ったスクリーンショット（本番や別サーバのページを含む）もここに入る。後の別の
  brainstorm で足す。
- PL5 ページを全部回ってスナップショットを取ること。取るのは表示中のページだけ。
- PL6 kemi が JSX などのコンポーネントを自分で描くこと。Storybook や開発サーバのループバックの
  URL で出したものを、ページとして見る。

## 委譲

- DL1 中継に使うクレートの選定（[D5](kemi.md#委譲) に含める）。[R-DEPS](kemi.md#r-deps-依存) と
  「WebSocket は中身を解釈しない」を守れば、どのクレートでも振る舞いは同じ。
- DL2 要素の対応づけの方法。[R-PAGE-DIFF](#r-page-diff-差分) の 2 つの約束を満たせば、利用者から
  見える差分は同じ。
- DL3 差し込むスクリプトとスナップショットの中の形（直列化の方法）。
  [R-PAGE-SNAPSHOT](#r-page-snapshot-スナップショット) の見た目と sandbox の約束を満たせば同じ。

## 却下

- RL1 kemi が撮るスクリーンショットで前後を比べる（理由: 画面の大きさや解像度で縮尺がずれ、比べにくい）。
- RL2 変更前のコードで開発サーバをもう 1 つ動かして並べることを既定にする（理由: 依存の導入と起動が
  毎回 2 つ分要る）。
- RL3 案をコードで作って切り替えることを既定にする（理由: 切り替えのたびに待つ）。
- RL4 案の切り替えの操作を対象の横に浮かせる（理由: 判断したい周りの見た目を隠す。試作で
  ロゴの横に置いたらサイト名を隠した）。
- RL5 git リポジトリの外で `--live` を拒む（理由: 試作段階のページを見るだけの使い方を締め出す）。
- RL6 公開中のサイトや別サーバのページを中継して描き込む（PL1。理由: 認証・Cookie・CSP で壊れやすい。
  エージェントが撮ったスクリーンショットで代わりになる）。
- RL7 kemi が自分でスクリーンショットを撮る（理由: ブラウザを操作する仕組みは作らない（PL3）。
  撮るのはエージェント）。
- RL8 kemi が JSX のコンポーネントを自分で描く（理由: プロジェクトごとにバンドラーと設定が違い、
  それを抱え込むことになる）。

## 未決

- UL1 `--live` 独自の性能の数字（スナップショットを取る時間、差分の計算、中継の遅れ）。
  Rust の中継を作った後に測って決める（決める人: 利用者、計測の後）。今のモードの性能の
  約束は変えない（[R-VERIFY](kemi.md#r-verify-検証)）。
- UL2 エージェントが撮ったスクリーンショットを kemi に渡す方法（入力の形、`kemi reply` に画像を
  付けるか、など）（決める人: 画像の仕様の brainstorm）。
