# kemi 仕様: セッションの保存と復元

[kemi 仕様](kemi.md) の一部。submit せずに終えたレビューの保存と復元。
用語の定義は `CONTEXT.md`、成功条件と反例の書き方は [kemi 仕様](kemi.md) の冒頭にある。

---

## R-SESSION セッションの保存と復元

形式4・世代・説明の保存と復元は [R-EXPLANATION-SESSION](explanation-contracts.md#r-explanation-session-保存と復元) を適用する。以下の形式2/3の記述に優先する。

未 submit のレビューをセッションとしてディスクに残し、あとから当時の差分のまま復元する。

**要件**

- 起動に成功したレビューは、submit するまでセッションとして残る。セッションは次を持つ:
  - 復元に使うレビューの写し。両グループ単位のレビューの全体で、ページの題
    （`title` / `subtitle` / `meta`）と `approval` を含み、変更ファイルの左右の内容を
    gzip で圧縮して持つ。内容にはバイナリ（`R-RENDER` の画像）も含め、下の上限に数える。
  - セッション状態（コメント、見た、折りたたみ、解決）。折りたたみはファイルごとの
    畳みの上書き（`R-VIEW`）とする。
  - セッションの情報（`id`、作成と最終更新の時刻、元のワークスペースのパスと識別、
    入力モードと範囲、`title`、起動時に開く方のグループ単位の全ファイル数、写しの状態）。
    写しの状態は「未完成」「使える」「使えない（理由つき）」のどれか。
- `--live` のセッションは写しを持たず、復元で動いているページにつなぎ直す。スナップショットと
  描き込みの画像を `<id>.files/` に置く（[live.md](live.md#r-page-session-保留と復元)）。
  写しの状態による一覧と復元の規則（下）の外で、一覧と復元の対象にする。1 セッション 20 MB の
  上限は `<id>.files/` の大きさで判定し、全セッション合計の 500 MB には `<id>.files/` も数える。
  エージェントとのつなぎ先は `<id>.endpoint`（[agent-channel.md](agent-channel.md#r-agent-link-つなぎ先と安全)）。
  どちらもセッションと同じ権限で置き、セッションを消すときに一緒に消す。
- セッション状態には返信・発言・案の選択と、往復の続きに要るもの（どこまで渡したか、
  `kemi wait` がまだ受け取っていない起きたこと、`kemi wait` が一度でも呼ばれたか）も入る。
  コメント・返信・発言には、書いた順をレビュー全体で比べられる通し番号をサーバが振って
  入れる（会話パネルの並び、`R-VIEW`。結果 JSON には出さない）。セッション形式の版を 3 に上げ、セッション
  形式の版 2 のセッションも読む（2 に無い項目は空として読む。通し番号は、コメントを作成順に
  並べ、各コメントのすぐ後にその返信を作成順に置いた順で振る）。
- 置き場所は結果ファイルと同じ根の下の `sessions/`（決め方は `R-RESULT` と同じ。
  unix では `$XDG_STATE_HOME/kemi/sessions/`）。ファイルとディレクトリの権限も
  `R-RESULT` と同じ（unix はファイル `0600`、ディレクトリ `0700`）。
- セッション 1 つの中身は 2 つのファイルに分けて置く。名前と入れ分けは契約とする。
  - `<id>.session` — セッション状態とセッションの情報。
  - `<id>.payload` — 復元に使うレビューの写し。写しの状態が「使える」でないセッションには
    無い。

  `<id>.session` に入るのはセッション状態とセッションの情報だけで、凍結したレビューの
  メタデータ（グループとファイルの一覧、題、`approval`）は写しの一部として `<id>.payload` に
  入れる。状態を書く費用が、写しの大きさにもレビューのファイル数にも左右されないようにする
  ため。ロックのファイル（D13）と、書き込み中の一時ファイルも同じディレクトリに置く。
  どちらもセッションの中身ではなく、名前は実装が決める。
- `id` は 26 文字の ULID（例 `01K5...`）。同じ時刻に作っても衝突しない。一覧の並びは
  `id` の文字列ではなく、記録した最終更新の時刻で決める。
- 写しは、起動時に計算するメタデータと、`api/review` の最初の応答を返した直後に読む
  内容から作る（起動を待たせない）。両グループ単位のメタデータと内容がそろった時点で
  完成とする。
- 復元では、完成している写しを作り直さない。読み直しも書き直しもしないので、復元して
  状態を変えなければ最終更新は進まず、一覧の並びも変わらない。
- `<id>.session` の写しの状態が「使える」のとき、その `<id>.payload` は必ずある。逆に、
  `<id>.session` が無いか、あっても写しの状態が「使える」でない `<id>.payload` が残ることは
  許す（掃除で消す）。2 つのファイルを同時に差し替えることはできないので、書く順序でこの
  向きを保つ。写しを保存するときは `<id>.payload` を書いてから `<id>.session` を書き、写しを
  捨てるときとセッションを消すときは `<id>.session` を先にする。どちらの向きでも、途中で
  止まったときに残るのは、どの `<id>.session` からも「使える」と指されていない
  `<id>.payload` だけになる。
- コミット範囲のセッションは、起動時に解決した `from` と `to` の完全な sha を範囲と
  して書き、復元時の由来と「このコミットで見る」はその sha で計算する（`R-ORIGIN`）。
- セッション状態は変更のたびに書く。書き込むのは `<id>.session` だけで、`<id>.payload` には
  触らない。状態を変える操作の費用が写しの大きさに左右されない。書き込みは
  一時ファイルから名前を変える原子的な差し替えとし、途中で失敗したファイルがセッション
  として読まれないようにする。強制終了（kill -9）やクラッシュでも、最後に書けたところ
  までは残る。
- セッション状態の書き込みに失敗しても、レビューは終わらせない。stderr に警告を出し、
  終了コードも変えない（結果ファイルの保存の失敗と同じ扱い。`R-RESULT`）。
- 起動中のレビューはセッションのロックを取り、submit か保留で解放する。ロックは、その
  セッションのファイルを何か書く前に取る。ロック中のセッションの `kemi --resume` は理由を
  stderr に出して終了コード 2。プロセスが残したロックは、記録した pid の生死で見分けて奪う。
- submit を確定したら、結果ファイルを書く（失敗は警告のみ。`R-RESULT`）→ セッションを
  消す → stdout に JSON を出す、の順で進める。
- 終了コード 130 は、保留（Ctrl+C / SIGTERM）と、選択の取り消し（Esc / Ctrl+C）の
  両方を指す（`R-SUBMIT`）。保留ではセッションを残し、復元できるセッションが残るときは
  stderr に機械が読む 1 行 `kemi: resume with: kemi --resume <id>` を出す。実行時
  エラー（終了コード 2）でも同じく、復元できるセッションが残るならこの行を出す。
  この行以外の案内の文言は契約としない。
- 写しの状態が「使える」でない、または「使える」なのに `<id>.payload` が無いセッションは、
  状態と情報だけを残し、一覧と復元の対象にしない（手で読めばコメントを回収できる）。
  id を指定した `--resume` は理由を stderr に出して終了コード 2。保存すべき状態が 1 つも
  無く写しも無い場合は、セッションを残さない。
- 写しの上限は 1 セッション 20 MB、全セッション合計 500 MB（どちらも圧縮後のバイト数。
  合計には状態と情報も含める）。1 セッションの大きさは `<id>.session` と `<id>.payload` の
  合算とし、1 セッション 20 MB の上限は `<id>.payload` の大きさで判定する。上限を超えるか
  どうかは `<id>.payload` を書く前に決め、超える写しはディスクに書かない。セッションは
  全ワークスペース合計で、新しい方から
  100 件、または合計 500 MB の小さい方を残し、超えた分を最終更新の古い順に消す。
  掃除はセッションを書くときに行い、ロック中のセッションは消さず、合計にも数えない。
  復元できないセッションも件数と合計に数える。
- 掃除では、`<id>.session` が無い `<id>.payload` を、起動中のレビューが持っていなければ
  消す。掃除はこの判定にセッションの中身を読まず、ディレクトリの一覧だけで決める。写しを
  書いてから `<id>.session` を書くまでの間、起動中のレビューは一時的にこの形になるが、その
  レビューはロックを持っているので消さない。
- 写しの状態が「使える」でなくなったときは、`<id>.session` を書いた後にその `<id>.payload` を
  消す。掃除を待たない。
- 強制終了で「`<id>.session` の写しの状態が『使える』でないのに `<id>.payload` がある」形が
  残ることはある。掃除はこれを見分けないが、そのセッションの大きさは 2 ファイルの合算で
  数えるので、上の件数とバイト数の上限に当たれば 2 ファイルとも消える。放置しても
  `sessions/` 全体が上限を超えて増えることはない。
- `kemi --resume [<id>]` で復元する。復元は同じ `id` のセッションを続けるもので、
  新しいセッションは作らない。`id` を指定したときは、そのセッションをどのディレクトリ
  からでも復元する。元のワークスペースが無くても復元できる。
  - `id` を省略したときは、標準入力が端末なら選択の画面（TUI）を出す。端末でなければ、
    復元できるセッションがあるときに限り、一覧を stdout に 1 行 1 件のタブ区切りで
    出して終了コード 0 で終わる。1 つも無ければ stdout に何も出さず、理由を stderr に
    出して終了コード 2。指定されていても、この起動では `--port` / `--bind` / `--no-open`
    を使わない（使い方の誤りにはしない）。
  - 一覧と選択の画面の行は、`id`、最終更新、ワークスペース、モード、見た数 / 全数の
    5 列。値に含まれるタブと改行は空白に置き換える。見た数は状態から数え、全数は
    起動時に開く方のグループ単位の値。並びは選択の画面と同じく最終更新の新しい順。
  - 選択の画面は、復元できるセッションだけを最終更新の新しい順に並べる。日時は
    ローカル時刻の `YYYY-MM-DD HH:MM`。モードは worktree / staged はその名前、
    コミット範囲は元の `from..to`、manifest は `title`、`--live` は `live <URL>`（`<ファイル>` のときの URL は題と同じ）。取り消し（Esc と Ctrl+C）では
    何も変えず終了コード 130。
  - 存在しない `id`、復元できないセッションの `id`、`R-INPUT-6` に反するフラグの
    組み合わせは、理由を stderr に出して終了コード 2。
- 復元したレビューは次のとおり:
  - 差分はセッションの写しだけから作り、元の入力（コミット範囲、worktree、manifest）を
    読み直さない。写しに無いファイルは作らない。`--live` は例外（[live.md](live.md#r-page-session-保留と復元)）。
  - 見た、折りたたみ、コメント、解決は続きから始まる。ライブリロード（監視と更新
    バッジ）は出さない。表示モードとテーマはセッションに保存せず、ブラウザの
    localStorage に任せる（URL と token が変わる復元では初期値に戻りうる）。
  - 由来（`R-ORIGIN`）は、記録した範囲の sha を使って元のワークスペースの
    リポジトリから計算する。読めない場合はそのファイルの由来が「特定できない」に
    なり、レビューは続く。
  - `--port` / `--bind` / `--no-open` は通常の起動と同じに働く。URL と token は
    新しく作る（古い URL は使えない）。
  - submit の結果ファイルは、セッションの記録した元のワークスペースの識別で置く
    （`R-RESULT`）。復元したディレクトリは使わない。
- `--digest` と `--result` はセッションを作らない。
- 読めないセッション形式の版のセッションは、理由を stderr に出して終了コード 2。黙って空の
  レビューを出さない。id を省略した `kemi --resume` でも同じで、復元できるセッションが
  1 つも無い理由が「読めない版のセッションしか無い」ことであるときは、それが分かる理由を
  出す。「1 つも無い」とだけ告げない。理由を名指すのは読めない版の場合だけでよい。
  写しを失ったセッションは 1 つずつ事故で起き、上限超過や写しの未完成なら保留の時点で
  伝えている。版の食い違いは、利用者が何もしていないのに kemi を更新した時点で、
  すべてのセッションへ一斉に起きる。

**成功条件**

- `XDG_STATE_HOME` を一時ディレクトリにして `--worktree` で起動し、Ctrl+C で保留すると、
  stdout が空で終了コード 130、stderr の「resume with」の行に `id` があり、
  `kemi --resume <id>` で同じファイル一覧と内容のレビューが始まる。
- 保留の間にワークツリーのファイルを変えてから復元しても、表示される内容が変えた後の
  ものではなく、レビュー開始時のものである（人が確認）。
- 保留したセッションでコメントを付け、submit すると、結果ファイルが元のワークスペースの
  識別で置かれ、セッションが消える。
- manifest の `approval` を持つセッションを復元して submit すると、結果の JSON の
  `approval` が元の入力と同じ。
- セッションのファイルとディレクトリが unix で `0600` / `0700` になる。
- 写しを持つセッションの `<id>.payload` を gzip として読めないバイト列に置き換えてから
  状態を何度か保存しても、保存が成功し、`<id>.payload` がそのバイト列のままである
  （Rust のユニットテスト。時間は測らない）。
- `<id>.payload` を消すと、そのセッションが `--resume` の一覧に出ず、id を指定した復元が
  終了コード 2 になる（統合テスト）。
- `<id>.session` の無い `<id>.payload` を置いてからセッションを書くと、その `<id>.payload`
  が消える。起動中のレビューが持っているものは消えない（Rust のユニットテスト）。
- 写しを保存する経路では `<id>.payload` の書き込みが `<id>.session` より前にあり、写しを
  捨てる経路とセッションを消す経路では逆である（差分のレビューで確かめる）。
- 写しを持つセッションを保存したとき、写しにだけあるファイルのパス（セッション状態の
  どのコメントも指していないもの）が `<id>.session` に現れない（Rust のユニットテスト）。
- 写しの状態が「使える」でない `<id>.session` と `<id>.payload` が揃って残っていても、件数か
  バイト数の上限を超えた時点で 2 ファイルとも消える（Rust のユニットテスト）。
- 写しが上限を超える、または完成しないまま保留すると、stderr に復元できない案内が
  出て、一覧にそのセッションが出ず、id を指定した復元は終了コード 2。
- 101 件目のセッションを書くと、最終更新が最も古いセッションが消える。合計が 500 MB を
  超える場合も同じ。合計は `<id>.session` と `<id>.payload` の合算で数える。ロック中の
  セッションは消えず、合計に数えない。
- セッション状態の書き込みを失敗させても、レビューが続き、終了コードが変わらない。
- 起動中のレビューの `--resume` が、理由を出して終了コード 2。
- `kemi --resume` を `id` なし・標準入力が端末でない状態で実行すると、一覧が 5 列の
  タブ区切りで stdout に出て、終了コード 0 で終わる。復元できるセッションが無ければ
  stdout が空で終了コード 2。
- 復元したレビューで元のワークスペースのリポジトリを消してから開くと、由来が
  「特定できない」になり、レビューは続く（人が確認）。
- 復元したレビューに更新バッジが出ず、元の入力が変わってもページの内容とコメントが
  変わらない（ブラウザ自動化で確認）。
- 読めないセッション形式の版のセッションを復元すると、理由を出して終了コード 2。
- セッション形式の版 2 で保留したセッションを、ライブ改訂の kemi で復元できる（cargo test。
  セッション形式の版 2 の `<id>.session` を固定のバイト列で置く）。
- `kemi --digest` と `kemi --result` の前後で `sessions/` の内容が変わらない。
- `kemi --resume` に `--digest` を付けると終了コード 2。復元できるセッションが 1 つも
  無い `kemi --resume` は理由を出して終了コード 2。
- 読めないセッション形式の版の `<id>.session` だけがある状態で、端末でない標準入力の
  `kemi --resume` を実行すると、stdout が空・終了コード 2 で、stderr が読めない版の
  セッションがあることを伝える（人が確認）。

**反例**

- 保留するとコメントが消える。
- 見たの印を付けるたびに写しを書き直し、大きなレビューほどディスクへの書き込みが増える。
- どの `<id>.session` からも指されていない `<id>.payload` が消されずに残り続ける。
- 掃除がセッションの中身を読み、状態を書くたびに `sessions/` 全体を読み直す。
- 写しの状態が「使える」なのに写しのファイルが無いセッションが一覧に出て、選ぶと開けない。
- 読めない版のセッションだけが残っている `kemi --resume` が、セッションを 1 つも保留して
  いない場合と同じ案内で終わる。
- 復元したレビューが、現在のワークツリーの内容を出す。
- 復元のたびに新しいセッションができ、同じレビューが一覧に増え続ける。
- 大きすぎるセッションが一覧に出て、選ぶと内容の欠けたページが開く。
- セッションが消されずに増え続ける、または他の利用者が読める権限で作られる。
- 復元したレビューの submit 結果が、復元に使ったディレクトリの識別で置かれる。
- 二つ目の復元が同じセッションに書き込み、コメントが混ざる。
- 元プロセスが動いているセッションを復元できてしまう。
- 復元したレビューに更新バッジが出て、写しと違う内容が表示される。
- 読めないセッション形式の版のセッションが、空のレビューとして黙って開く。

## 作らないもの

- P14 写しを欠いたセッションの復元。内容の欠けたページを出さず、復元できないものとして
  案内する（`R-SESSION`）。

## 委譲

- D12 セッションのそれぞれのファイルの中の形式（gzip した内容の入れ方、状態と情報の
  並べ方、セッション形式の版の持ち方）。どの形式でも `R-SESSION` の上限、掃除、復元の
  内容は同じ。写しと状態を別のファイルに置くことと、その名前と入れ分けは `R-SESSION` の
  契約で、ここには含まない。
- D13 セッションのロックの実装（ロックのファイル名と、残ったロックを奪う判定の細部）。
  どの実装でも二重復元は防がれ、強制終了の後に復元できる。
- D14 端末の選択画面の見た目の細部と、`id` の生成方法。どちらも `R-SESSION` の形式と
  並びを満たす限り、どの実装でも同じ。

## 却下

- R20 セッションの写しを差分パッチとして持ち、復元時に old 側を再構成する（理由:
  復元の実装が重く、失敗したときの被害が大きい）。
- R21 復元のときに元の入力を読み直し、変わっていたら現在の内容を出す（理由: 当時の
  差分を再現できず、コメントの `quote` と表示が食い違う）。
- R22 同じセッションを二重に復元できるようにする（理由: コメントが混ざる）。
- R23 ページに保留ボタンを置く（理由: プロセスを落とす運用と相性が悪く、状態の保存が
  操作に依存する）。
- R24 選択を番号の入力だけにする（理由: 選ぶ操作を矢印で行える対話の体験を優先した）。
