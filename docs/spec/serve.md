# kemi 仕様: 配信

[kemi 仕様](kemi.md) の一部。サーバの配信モデルと、供給元の変化を画面へ届けるライブリロード。
用語の定義は `CONTEXT.md`、成功条件と反例の書き方は [kemi 仕様](kemi.md) の冒頭にある。

---

## R-SERVE 配信モデル

差分表示版の発行と保存は [R-EXPLANATION-BASE](explanation.md#r-explanation-base-差分表示版と鮮度) と [R-EXPLANATION-SESSION](explanation-contracts.md#r-explanation-session-保存と復元) を適用する。

**要件**

- 常に HTTP サーバを立てる。既定では `127.0.0.1` にだけバインドし、他端末から
  到達できない。静的 HTML は書き出さない。
- 起動時に計算するのは、起動時に表示するグループ単位のファイル一覧・状態・統計・
  グループ情報まで。コミット範囲のもう片方のグループ単位は、`api/review` の最初の
  応答を返した後に裏で作る（`R-UNIT`）。行データと由来（`R-ORIGIN`）と描画（`R-RENDER`）は
  ファイルが表示された時に初めて計算して配信する。ただし行データは、`n` / `p` の
  移り先を決めるために、そのファイルに止まる場所があるかを確かめる時にも計算して
  よい（`R-NAV`）。
- バインド先は `--bind <IPv4>` で変えられる（既定 `127.0.0.1`、`0.0.0.0` は全
  IPv4 インターフェース）。ループバックは `127.0.0.0/8` とする。
- URL は `http://<host>:<port>/s/<token>/` の形。`token` はセッションごとの
  ランダム値で、URL を知らないページからの API 利用を防ぐ。`<host>`（以下、
  共有アドレス）は、具体アドレスへのバインドならそのアドレス、`0.0.0.0` なら
  既定経路のローカルアドレス（std の UDP connect で得る。パケットは送らない）
  にする。`0.0.0.0` で特定できないときは `127.0.0.1` のままとする。既定経路が
  VPN などのときは LAN のアドレスにならないことがあり、そのときは
  `--bind <自分のIP>` で指定する。
- 共有アドレスの取得は、特定できない場合も含めてテストから差し替えられる形に
  する（差し替えの形は実装が決める）。取得と `Host` の検証に新しい依存は
  足さない。
- 非ループバックで待つときは、URL の行の後に警告を 1 行出す。警告は英語で、常に
  `kemi: exposed on the LAN;` で始める。共有アドレスを特定できたときは、続けて
  URL を知る人は誰でも閲覧と submit ができ、平文 HTTP であることを述べる固定の
  1 文にする:
  `kemi: exposed on the LAN; anyone with the URL can read the diff and submit over plain HTTP.`
  特定できないときは、続けて取得できなかったことと `--bind <自分のIP>` で明示
  できることを述べる（文面は実装が決める）。どちらの場合も、公開のリスク
  （誰でも閲覧と submit ができること、平文 HTTP）を述べる。
- ブラウザを自動で開くときは URL を開く（`0.0.0.0` のときは `127.0.0.1` に
  読み替える）。
- 公開が他端末から実際に届くかは OS とネットワークに依存し、kemi は関与しない
  （ファイアウォールや転送の設定を行わない）。
- API は同じオリジンのページからの呼び出しだけを受理する（`Origin` と `Host` を
  検証する）。例外はエージェント用の API で、ループバックからの `Origin` を持たない要求
  だけを受理する（[agent-channel.md](agent-channel.md#r-agent-link-つなぎ先と安全)）。クロスオリジンの `POST` は拒否する。`POST` の `Host` は port が
  待ち受け port と一致し、ホスト部が `127.0.0.0/8`・バインドした具体アドレス・
  共有アドレスのいずれかであるときだけ受理し、`Origin` は `http://` + 受理した
  `Host` と完全一致することを要する。許可をこの 3 つに限るのは、公開の範囲を
  広げず DNS rebinding を防ぐため。共有アドレス以外のローカルアドレス経由で
  開かれたページの `POST` は 403 になる（利用者には URL を案内するため通常は
  起きない。別のアドレスで使いたいときは `--bind <そのアドレス>` で起動する）。
- API の契約（最低限の一覧。由来やもう片方のグループ単位を届けるためなどの
  エンドポイントの追加は D7）:
  - `GET /s/<token>/api/review`: グループとファイルのメタデータ。各ファイルは
    不透明な `id` を含む。
  - `GET /s/<token>/api/file/<id>`: そのファイルの整列済み行データ。
  - `POST /s/<token>/api/comment`: コメントの追加・編集・削除・返信・解決（`R-COMMENT`）。
  - `POST /s/<token>/api/submit`: submit（`R-SUBMIT`）。
  - `GET /s/<token>/api/events`: `R-LIVE` の通知と、エージェントの返信・発言・状態の通知（SSE）。
  - エージェント用の API（`kemi wait` / `kemi reply` が使う）。受理の条件は
    [agent-channel.md](agent-channel.md#r-agent-link-つなぎ先と安全)、URL の形は DA1。
  - `--live` では中継のための 2 つ目のポートを持つ（[live.md](live.md#r-page-proxy-中継と安全)）。
  - `GET /s/<token>/api/image/...`: 画像のバイト列（`R-RENDER`）。2 種類あり、どちらも
    `GET` だけで、URL の形は D7。
    - レビュー対象の画像の旧・新: kemi がそのレビューで読んだバイト列をそのまま配る
      （入力モードを問わない。復元では写しから）。
    - Markdown の相対パス画像: リポジトリの中に正規化できるパス（symlink は辿らず、
      symlink そのものは配らない）で、`R-RENDER` の画像形式で、上限以下のものだけ。
      manifest と復元では配らない（`R-RENDER` の表）。
    - どちらも条件を満たさないものは 404。応答には、拡張子から決めた `Content-Type` と
      `X-Content-Type-Options: nosniff`、`Content-Security-Policy: sandbox` を付ける。
      同じオリジンで直接開かれた SVG の中のスクリプトが kemi の API に届かないため
      （sandbox の文書は別オリジン扱いになる）。
- 内部 API の JSON 形（行データのフィールド名など）は実装が決める（D7）。
- 複数の端末から見られていても、セッションは 1 つで、利用者は区別しない。コメントに
  著者は付かない（利用者の認証を作らない。P5）。返信と発言が持つ書いた人は「人間」か
  「エージェント」かだけで、人間の中を区別しない（[agent-channel.md](agent-channel.md)）。submit の受理は 1 回だけの既存の
  契約のまま（`R-SUBMIT`）。
- セッション状態（コメント、見た、折りたたみ、解決）はサーバのメモリに置き、
  変更のたびにセッションファイルへも書く（`R-SESSION`）。プロセス終了で失われるのは
  写しの作成が終わる前の内容だけ。submit を確定した結果の JSON は結果ファイルに
  残す（`R-RESULT`）。ブラウザの localStorage は表示の好み（表示モード・テーマ・会話パネルの
  開閉と幅）と
  下書きにのみ使う。

**成功条件**

- 10,000 ファイルのフィクスチャで、プロセス開始から `api/review` の初回応答までが
  1 秒未満（release ビルド、`scripts/measure-startup.sh`、3 回の中央値）。
  この条件は起動時に作るグループ単位に適用する。
- 起動と `api/review` はファイル内容を読まない（テストで、内容取得の呼び出し
  回数が 0 であることを確認する）。行データは `api/file` の応答に必要な時に
  初めて計算する。
- URL の token 無しの API 呼び出しが 404 または 403 で拒否される。
- `Origin` の異なる `POST` が拒否される。
- `kemi --bind 0.0.0.0 --port 0 --no-open` の stderr から URL を取り出し、その URL の
  `api/review` が応答する。URL の行の後に `kemi: exposed on the LAN;` で始まる警告行が
  ある。
- 既定で起動したとき、URL が `http://127.0.0.1:<port>/s/<token>/` の形で、警告行が
  無い。
- 共有アドレスの取得をテストから差し替えてアドレス A を返させたとき、URL の host が
  A になり、警告が固定の 1 文になる。`Host: A:<port>` と対応する `Origin` の `POST`
  が受理され、他のアドレスを `Host` に持つ `POST` は 403 になる。
- 共有アドレスを特定できないように差し替えたとき、URL が
  `http://127.0.0.1:<port>/s/<token>/` になり、警告が `kemi: exposed on the LAN;` で
  始まり `--bind` を含み、LAN 側のアドレスを `Host` に持つ `POST` が 403 になる。
- `--bind 0.0.0.0` でブラウザを自動で開くとき、開かれる URL が `127.0.0.1` である
  （人による確認）。
- 2 つのクライアントで同じ URL を使い、片方で付けたコメントと見たがもう片方から
  見える。submit の JSON のコメントに著者のフィールドが無い。

**反例**

- 起動時に全ファイルの内容を読んで行データを作る（10,000 ファイルで 1 秒を超える）。
- 最終形で起動したのに、コミットごとの単位を作り終えるまで `api/review` が返らない。
- `--bind` 無しで `127.0.0.1` 以外にバインドされ、他端末から到達できる。
- 非ループバックで待つのに警告が出ない。または警告が公開のリスクを述べない。
- `0.0.0.0` のとき任意の `Host` を受理し、別オリジンのページから `POST` が届く。
- 許可の範囲が URL とバインドで決まらず、実行環境のインターフェース一覧に広がる。
- URL の token 無しで API が応答する。
- 別オリジンのページからの `POST` が受理される。

## R-LIVE ライブリロード

差分取り込みの世代と説明通知の分離は [R-EXPLANATION-BASE](explanation.md#r-explanation-base-差分表示版と鮮度) を適用する。

**要件**

- 監視対象は「レビューの新側の供給元」に限る:
  - worktree（`--live` のコードの見方を含む）: 作業ツリー全体。起動時の差分に無かったファイルの
    変更・追加・削除も検知する（エージェントが新しく触ったファイルを見落とさないため）。`.git` の中と、
    git が無視するもの（`.gitignore` などで無視したパス）は見張らず、そこへの書き込みでは
    バッジを出さない。見張りの登録は起動の応答を待たせない。見張り方は OS で分ける:
    - Linux: ディレクトリごとに見張り、無視したディレクトリの下には潜らない。見張るディレクトリは
      1 レビューで 10,000 個まで。超えるか、OS の見張りの上限に当たったら、起動時の差分のファイル
      だけを見張る形に落とし、そのことを stderr に 1 回出す。
    - macOS と Windows: 作業ツリーの根に OS の再帰の見張りを 1 つだけ付け、`.git` の中と無視する
      ものへの変化は届いた後で捨てる。ディレクトリごとに見張りを開かないので、見張りがエージェントの
      ディレクトリの改名や削除を妨げない。根を見張れなければ Linux と同じく落とす。
  - manifest の `new_path`: 対象ファイル
  - コミット範囲: `--to` の ref（既定 `HEAD`）。ref の更新は検知の対象。
    それ以外の `.git` 内部の書き込みは無視する。
  - `--live <ファイル>`: コードの見方は worktree と同じ。これとは別に、ページの見方のために
    配れる範囲のファイルを見張る（[live.md](live.md#r-page-mode-起動)）。
- 変更を検知したら SSE でブラウザに「更新あり」を知らせ、バッジを表示する。
- 再取得は人の操作で行う。勝手にスクロール位置や表示内容を変えない。例外は 2 つ:
  `--live` のページの見方で、動いているページ（`<ファイル>` のときは保存での読み込み直しを含む）、
  案の差し替え、変化の一覧と印、ページのツリーの変化の数はその場で変わる
  （[live.md](live.md#r-page-view-ページの見方)）。エージェントの返信・発言・状態は届いたらその場で
  出る（[agent-channel.md](agent-channel.md)）。どちらもスクロール位置は変えない。ただし
  会話パネルの並びは、一番下を見ているときだけ新しいものについていく
  （[R-AGENT-HAND](agent-channel.md#r-agent-hand-渡す)）。
- 再取得後、内容が変わったファイルのコメントは `outdated` 表示にする（`R-COMMENT`）。
- コミット範囲では、作ってあるグループ単位を両方とも取り直す。見たとコメントは
  グループとパスが同じファイルに引き継ぐ。新しいコミットは、コミットごとの単位に
  未読のグループとして加わる。
- 履歴の書き換え（amend や rebase）でコミットごとのグループが消えたときは、そこに
  付いていたコメントを submit JSON に元の `group_id` と `group_title` のまま
  `outdated: true` で入れる。画面では、会話パネルに「消えたコミット」として出す。
- 監視の追加・更新は debounce し、短期間の複数書き込みでバッジを点滅させない。
- 復元したレビューでは監視も更新バッジも行わない（`R-SESSION`）。例外は `--live` のコードの
  見方で、復元時の作業ツリーを読み、監視も続ける（[live.md](live.md#r-page-session-保留と復元)）。

**成功条件**

- worktree モードでファイルを外部から変更すると、バッジが出て、押すと差分が更新
  される。起動時の差分に無かった追跡済みのファイルを変えたときと、新しいファイルを
  作ったときも同じ（e2e）。
- `.gitignore` で無視したディレクトリの下に書き込んでも、バッジが出ない（e2e）。
- Linux で、見張るディレクトリが 10,000 個を超える作業ツリーでは、起動時の差分のファイルの変更で
  バッジが出て、stderr に落とした旨が 1 回出る（e2e）。
- worktree で起動している間に、作業ツリーの中のディレクトリを改名し、消せる（e2e。Windows を含む
  全 OS の CI で）。
- 追跡しているファイル 10 万個のうち 100 個だけを変え、無視したディレクトリ 5 万個を持つ作業ツリー
  （`scripts/gen-fixture.sh` で作る）で、起動から一覧までが 1 秒未満で、作業ツリー全体を見張る前の
  kemi より 1 割以上遅くならない（`scripts/measure-startup.sh` で測る。人が確認）。作業ツリー全体の
  見張りが効くまでの時間も測って報告する（起動時の差分のファイルは先に見張る）。
- 変更後にページのスクロール位置が勝手に変わらない。
- `--group-by commit` で `--to HEAD` の状態で新しいコミットを作るとバッジが出る。
- 再取得の後、コミットごとの単位に新しいコミットのグループが未読で加わり、既存の
  グループの見たとコメントが残る。
- amend でグループが消えた後に submit すると、そのグループのコメントが元の
  `group_id` のまま `outdated: true` で入る。

**反例**

- リポジトリ全体を、無視したディレクトリ（`node_modules`、`target` など）まで再帰監視して、
  数万ファイルのリポジトリで監視が破綻する、またはビルドの出力でバッジが出続ける。
- エージェントが起動時の差分に無かったファイルを直しても、バッジが出ず、コードの見方に
  出ない。
- 変更のたびに自動で再読込し、読んでいた位置を失う。
- 対象外の `.git` 書き込みでバッジが出続ける。

## 作らないもの

- P5 複数ユーザーと認証。
- P10 静的 HTML の書き出し（`--out`）。

## 委譲

- D7 内部 HTTP API の JSON 形（`R-SERVE` のエンドポイント以外の形）と、`R-SERVE` の
  一覧に無いエンドポイントの追加。どちらも画面の振る舞いを変えず、ページと
  サーバの間でだけ使う。

## 却下

- R2 静的 HTML 書き出し（理由: 大規模初期表示とコメント機能の両方で不利）。
