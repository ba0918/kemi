# 比べる相手 仕様

- Status: 草稿（ライブ改訂）
- 用語の定義: `CONTEXT.md`
- 親の仕様: [動いているページのレビュー](live.md)。本体の仕様: [kemi 仕様](kemi.md)

結果を一文で: **`--live` の見る対象の横に並べる「比べる相手」を、前のスナップショットか、
ページに割り当てたモックの HTML から選び、必要なときに並べるか重ねて透かして見比べられるようにする。**

各要件の「成功条件」と「反例」の書き方は [kemi 仕様](kemi.md) の冒頭と同じ。証拠の出所は
[R-VERIFY](kemi.md#r-verify-検証)。

## R-PAGE-REF 比べる相手

**要件**

- 比べる相手の種類は、スナップショット（[R-PAGE-SNAPSHOT](live.md#r-page-snapshot-スナップショット)）と
  モック（[R-PAGE-MOCK](#r-page-mock-モック)）。デザイン画像は後の別の仕様で足す
  （[live.md の作らないもの](live.md#作らないもの)）。種類が増えても、並べ方・重ね方・選び方は
  この節のまま変えない。
- 比べる相手はページ（URL のパスとクエリ。`#` から後ろは無視）ごとに選ぶ。画面の比べる相手の
  選択でいつでも切り替えられる。
- 比べる相手の選択肢は、「自動」と、個々のスナップショット（渡した時点・開始時・手で取った時点）と
  モック（[R-PAGE-MOCK](#r-page-mock-モック)）。並びは、自動 → 渡した時点 → 開始時 → 手で取った
  時点 → モック。
- 自動は、今のページと表示幅のスナップショットから次の順に最初に見つかったものを選ぶ: 最後に
  渡した時点 → レビューの開始時 → 最後に手で取ったもの。どれも無ければ「記録されていない」と出す
  （[R-PAGE-VIEW](live.md#r-page-view-ページの見方)）。自動を選んでいる間は、選択にも選択肢にも、
  いま自動で選ばれている実物の名前（例: 最後に渡した時点のどれか）を出し、自動の規則を選択肢の
  そばに短く出す。
- 既定は、そのページにモックを割り当てていればモック、無ければ自動。
- 比べる相手の選択（選択肢から選んだもの、手で取って切り替わったもの）は、レビュー画面を開いて
  いる間だけページごとに覚える。読み込み直しと復元では覚えておらず、既定に戻る（セッションに
  入れない）。開いている間は、人が選び直すまで変えない。
- スナップショットを選ぶときは、時点（渡した時点・開始時・手で取った時点）を選ぶ。表示幅を
  切り替えても選んだ時点は変わらず、その時点にその幅のスナップショットが無ければ「記録されて
  いない」と出す。
- 手で取る操作（[R-PAGE-SNAPSHOT](live.md#r-page-snapshot-スナップショット)）でスナップショットが
  取れたら、そのページの比べる相手を取ったスナップショットに切り替え、取ったことを知らせる。
  見比べ方（下）は変えない。見る対象だけの見比べ方のときは、知らせに並べる見比べ方へ切り替える
  操作を付ける。取れなかったときは比べる相手を変えない。取ったスナップショットへの切り替えは、
  選択肢から選んだときと同じく、レビュー画面を開いている間は人が選び直すまで変えない（次に
  渡しても自動に戻さない）。
- 見比べ方は 3 つ。既定は見る対象だけで、見比べたいときに並べるか重ねて透かすへ切り替える。
  - 見る対象だけ: 見る対象を 1 枚で出し、比べる相手は出さない。比べる相手の選択は続いていて、
    それがスナップショットなら変化の一覧と見る対象の側の印は出す
    （[R-PAGE-DIFF](live.md#r-page-diff-差分)）。
  - 並べる: 見る対象と比べる相手を同じ表示幅で並べる（[R-PAGE-VIEW](live.md#r-page-view-ページの見方)）。
    両方のページの上端を同じ高さにそろえる（片方の見出しの名前が長くても、見出しの高さでずらさない）。
  - 重ねて透かす: 比べる相手を見る対象の上に、同じ表示幅・左上ぞろえで重ねる。透かし具合を
    変えられる。スクロールは両方でそろえる。どの種類の比べる相手でも使える。重ねている間も、
    要素を選ぶ・矢印・ペンの操作は下の見る対象に届く（重ねた比べる相手は操作を受けない）。
    重ねている間は、いま何が見えているかを見出しに出す: 両方の名前と透かし具合。透かし具合が
    端のとき（片方だけが見えているとき）は、見えている方がどちらかを出し、重ねて透かす見比べ方の
    ままであることも分かる書き方にする（見る対象だけの見比べ方の見出しと同じ書き方にしない）。
- 広い画面では、比べる相手の選択は並べるか重ねて透かすの間だけ出す。狭い画面での見比べ方と
  比べる相手の選択の置き場所は [R-PAGE-VIEW](live.md#r-page-view-ページの見方)（並べる・重ねて透かすは
  出さず、1 枚ずつ切り替える）。
- 変化の一覧と印（[R-PAGE-DIFF](live.md#r-page-diff-差分)）は、スナップショットと比べるときだけ出す。
  モックと比べるときは出さず、並べるか重ねて透かして見る。
- コメント（[R-PAGE-COMMENT](live.md#r-page-comment-コメントの場所)）は見る対象の側にだけ付ける。
  比べる相手の側には付けられない。

**成功条件**

- モックを割り当てたページを開くと、比べる相手がモックになり、変化の一覧が出ない。割り当てを
  外すと、最後に渡した時点のスナップショットに戻り、変化の一覧が出る（ブラウザ自動化）。
- 重ねて透かす表示で、透かし具合を変えると比べる相手の見え方が変わり、見る対象をスクロール
  すると比べる相手も同じだけ動く（ブラウザ自動化）。
- 並べた比べる相手の側で要素を選ぶ・描く操作をしても、コメントの場所が増えない。重ねて透かして
  いる間に要素を選ぶと、見る対象の要素がコメントの場所になる（ブラウザ自動化）。
- 渡す前のレビューで、開始時のスナップショットが既定の比べる相手になる（ブラウザ自動化）。
- 開いた直後は見る対象だけが出て、比べる相手の選択が出ない。並べるに切り替えると選択が出る
  （ブラウザ自動化）。
- 試験用のページの文字を変えながら 2 回渡してから並べると、比べる相手の選択は自動のままで、並べた
  比べる相手の側に 2 回目に渡した時点の文字が描かれる。選択に出ている名前は、選択肢の中の 2 回目に
  渡した時点の項目の名前を含む（ブラウザ自動化。名前の文言は決めず、両者が同じことだけを見る）。
- 重ねて透かす表示で透かし具合を変えると見出しが変わる。両端に寄せたときの見出しは、途中のときとも
  互いとも違い、見る対象だけの見比べ方の見出しとも違う（ブラウザ自動化。文言は決めず、違うことだけを
  見る）。
- 見る対象だけの見比べ方で手で取ると、見比べ方は変わらず、比べる相手が取ったスナップショットに
  なり、取ったことの知らせが出る。知らせの操作を押すと並べる見比べ方になり、取ったスナップショットが
  並ぶ（ブラウザ自動化）。
- 手で取って比べる相手が切り替わった後に渡しても、比べる相手は取ったスナップショットのまま。
  レビュー画面を読み込み直すと既定（自動）に戻る（ブラウザ自動化）。
- パスが 200 文字のモックを割り当てて並べ、比べる相手の見出しが見る対象の見出しより高くなる幅
  （折り返す幅）にしても、両方のページの上端の位置の差が 1px 以内（ブラウザ自動化）。

**反例**

- モックと動いているページの要素を対応させ、別物同士の差が変化の一覧に並ぶ。
- 比べる相手に描き込めて、エージェントがどちらを直すのか分からない。
- 重ねて比べる相手だけが見えているのに、見出しが見る対象の名前のままで、どちらを見ているか
  分からない。
- 「最新」と書いた選択肢が時刻順ではない規則で選ばれ、実際に何と比べているか分からない。
- 手で取っても画面が何も変わらず、取れたのか、どれと比べているのか分からない。
- 取ったものと比べて読んでいる途中に渡すと、比べる相手が勝手に別のものに替わる。
- 重ねて透かす見比べ方で端に寄せると、見る対象だけの見比べ方と見出しが同じになり、重ねている
  ことに気づかずに操作する。

## R-PAGE-MOCK モック

**要件**

- モックは、ページに割り当てた HTML ファイル。比べる相手の選択肢の最後の「モックのファイル」から
  割り当てる。選ぶと小さなパネルを開き、モックが何かの一行の説明、検索の欄、ファイルの一覧を出す。
  - 一覧は、配れる範囲（[R-PAGE-MODE](live.md#r-page-mode-起動)）の中の、git が無視しない
    `.html` と `.htm`（追跡中のものと、無視されない未追跡のもの）。範囲の中かは実体の場所で判定し、
    `.git/` の中は出さない。検索の欄でパスを絞り込める。git リポジトリの外で起動したときは
    （無視の判定が無いので）配れる範囲の中の `.html` と `.htm` をすべて出す。
  - 一覧に出すのは 200 件まで。超えたら、出している数と全体の数、検索の欄で絞り込めば出ることを
    示す（検索の結果にも同じ上限を掛け、そのときの全体の数は検索に合うものの数）。200 は、集める
    速さではなく目で探せる量で決めた（2026-10-07 の計測で、索引に 10 万ファイル・うち HTML 2 万の
    リポジトリでも、HTML を集めるのは約 60 ms）。
  - 一覧に無いファイル（git が無視するものなど）も、パネルの中の入力欄にパスを入れれば
    割り当てられる。
  - 割り当てはページごとで、表示幅は問わない（選んでいる表示幅で描く）。CLI のフラグは無い。
- 割り当てている間は、比べる相手の選択に割り当てたファイルの名前を出す。読み直す操作と外す
  操作は、選択の横のメニューに置く。見る対象だけの見比べ方の間は、変化の一覧の見出しからも同じ
  メニューを開ける（[R-PAGE-VIEW](live.md#r-page-view-ページの見方)）。外したら、取り消す操作つきで外したことを知らせ、取り消すと
  同じ割り当てに戻る。
- 割り当てられるのは、配れる範囲の中の `.html` か `.htm`
  だけ（一覧から選んでも、パスを入れても同じ）。モックが参照する CSS・画像なども配れる範囲の中から
  だけ配る。範囲の外のパスや HTML でないファイルは、理由を画面に出して断る。
- モックのスクリプトは動かす。レビュー画面と別のオリジンになる iframe（`sandbox` は
  `allow-scripts` だけ）に出し、レビュー画面にも kemi の API にも届かない。モックとそれが参照する
  ファイルは、ページのトークン（`/s/<token>/`）を含まない URL で配る。その URL はレビューごとに
  推測できない値を含み、配れる範囲のファイルしか返さない（方法は DC1）。スナップショットの
  スクリプトは今どおり止める（[R-PAGE-SNAPSHOT](live.md#r-page-snapshot-スナップショット)）。
- モックは、比べる相手として画面に出し始めるたびに、その時点のファイルを読む。出し始めるとは、
  モックが見えていない状態から見える状態になること、または描き直すこと: 比べる相手をモックに
  切り替えたとき、見る対象だけから並べるか重ねて透かすへ切り替えたとき、並べると重ねて透かすを
  切り替えたとき、狭い画面で比べる相手の 1 枚に切り替えたとき、ページを移ったとき、表示幅を
  切り替えたとき、読み直す操作を押したとき。出している間にファイルが変わっても勝手には描き直さない
  （[R-LIVE](kemi.md#r-live-ライブリロード)）。見る対象と同じファイルをモックにしてもよく、そのときも
  見る対象だけが保存で読み込み直される。
- セッションに保存するのは割り当て（ページとパス）だけ
  （[R-PAGE-SESSION](live.md#r-page-session-保留と復元)）。出すときにファイルが無ければ、
  読めないことを出す。

**成功条件**

- 配れる範囲の中の、CSS と画像を参照するモックを割り当てると、同じ表示幅でスタイルと画像ごと
  出る（ブラウザ自動化）。
- 配れる範囲の外のパスと `.txt` のファイルを割り当てようとすると、理由が出て割り当てられない
  （ブラウザ自動化）。
- JS で中身を描くモックが描かれる。そのモックのスクリプトから、`location`・親の画面の DOM・
  cookie のどれを読んでもページのトークンが得られず、トークンを付けて kemi の API を呼んでも
  `Origin` が `null` のため断られる（ブラウザ自動化）。
- 割り当てて保留し、モックのファイルを消してから復元すると、読めない旨が出る（ブラウザ自動化）。
- 作業ツリーに、追跡中の HTML、無視されない未追跡の HTML、git が無視する HTML、`.git/` の中の
  HTML、範囲の外を指すシンボリックリンクの HTML を置いてモックのパネルを開くと、一覧には前の
  2 つだけが出て、検索の欄で絞り込める。git が無視する HTML は、入力欄にパスを入れると割り当て
  られる（ブラウザ自動化）。
- git リポジトリの外の、起動したディレクトリの下の HTML が一覧に出る（ブラウザ自動化）。
- HTML を 201 個置いた作業ツリーで一覧を開くと、200 件だけが出て、出している数 200 と全体の数 201 が
  示され、検索の欄で絞り込むと、出ていなかったファイルが出る（ブラウザ自動化）。
- 割り当てたモックを外すと、取り消す操作つきの知らせが出て、押すと同じモックが比べる相手に
  戻る（ブラウザ自動化）。

**反例**

- 割り当てのパスに `../../other/secret.html` のような外のパスを入れると、配れる範囲の外のファイルが画面に出る。
- モックのスクリプトがレビュー画面のオリジンで動き、トークンを読む。
- 割り当ての入口がパスを入れる欄だけで、モックが何か、どのファイルを入れればよいか分からない。
- 押し間違えて外したモックを、パスを覚えていないと戻せない。
- HTML の多い作業ツリーで一覧を開くと画面が固まる。

## 委譲

- DC1 モックを配る URL の作り（ポート、推測できない値の持ち方）。トークンを含まないこと、
  レビューごとに推測できないこと、配れる範囲のファイルしか返さないことを守れば、利用者から
  見える振る舞いは同じ。
- DC2 重ねて透かすときにスクロールをそろえる方法（比べる相手を中身の高さで描いて外側で
  スクロールする、など）。両方が同じだけ動けば、利用者から見える振る舞いは同じ。

## 却下

- RC1 モックの一覧の上限を 500 件・1000 件にする（理由: 集める速さではなく目で探せる量で決める。
  それより多いときは検索の欄で絞り込む）。

## 未決

- なし（UC3 のモックの一覧の件数は 200 に決めた。[R-PAGE-MOCK](#r-page-mock-モック)）。
