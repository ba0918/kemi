# kemi 仕様: 描画表示

[kemi 仕様](kemi.md) の一部。Markdown・画像・表などの描画表示。
用語の定義は `CONTEXT.md`、成功条件と反例の書き方は [kemi 仕様](kemi.md) の冒頭にある。

---

## R-RENDER 描画表示

Markdown・表（CSV / TSV）・画像を、行の差分（ソース表示）ではなく描画した見た目
（描画表示）で読めるようにする。GitHub の rich diff に相当する。用語は `CONTEXT.md`
（描画表示 / ソース表示 / ブロック）。

**要件**

対象と切り替え

- 描画表示の対象は拡張子で決め、大小文字は区別しない。Markdown は `.md` / `.markdown`、
  表は `.csv` / `.tsv`、画像は `.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.svg`。
  改名では新側のパス、削除ファイルでは旧側のパスで判定する。
- 既定はソース表示。Markdown と表は、ファイルヘッダの "Rendered" / "Source" の
  切り替えとキー操作（割り当ては D15）で描画表示にする。ファイルごとの切り替えは
  ページを開いている間だけ覚え、セッションには入れない（復元でもソース表示に戻る）。
  ヘッダの他の操作と同じく、内容の取得が終わるまで切り替えは無効。
- 画像は切り替えを持たず、常に描画表示（`R-VIEW` のバイナリの規則の例外）。SVG だけは
  テキストなので切り替えを持ち、既定は描画表示（画像を並べる）、切り替えるとソース表示
  （テキストの差分）。
- 描画表示は表示モード（1 列 / 2 列）に関係なく 1 段で出す。画像だけ、2 列では旧と新を
  左右に、1 列では上下に並べる。
- 描画は表示時に計算する（`R-SERVE` の行データと同じ。起動時と `api/review` では
  計算しない）。
- 描画表示は行の仮想化と折りたたみを持たず、上限の範囲で文書全体を出す。

Markdown の描画

- 方言は GFM（表・取り消し線・タスクリスト・自動リンク・脚注）。`.mdx`、front matter の
  中身、数式は解釈しない（P18）。
- 先頭の front matter（1 行目がちょうど `---` で、その後にちょうど `---` だけの行が
  現れるまで）は切り離し、コード塊と同じ見た目の無地の塊として先頭に出す。閉じる
  `---` が無ければ front matter とみなさず、全体を Markdown として描画する。
- 生 HTML は解釈せず、テキストとしてエスケープして出す。
- リンクの `href` と画像の `src` は、前後の空白と制御文字を除いてから判定し、大小文字を
  区別しない `http` / `https` スキーム、`//` で始まらない相対パス、`#` 始まりだけを
  通す。それ以外（`javascript:` / `data:` / `//host` など）は無効にする。`#` 始まりを
  通すのはリンクの `href` だけで、画像の `src` では枠にする（断片はページの中の位置を
  指すもので、画像の中身を指さないため）。外部 URL の
  リンクは新しいタブで開き、`rel="noopener noreferrer"` を付ける。相対パスのリンクは
  リンクにせず、テキストとして出す（パスは `title` 属性で見える。kemi には飛び先の
  ページが無く、ページの URL 配下への遷移先をリポジトリの内容が作れないようにする）。
- コード塊は、そのファイルのハイライトの設定（`R-VIEW`）に従い、フェンスの情報文字列の
  言語でサーバ側にハイライトする。別の切り替えは持たない。
- 相対パスの画像は、その Markdown ファイルのディレクトリを基準に解決する。先頭の `/`
  はリポジトリの根。解決の元は、その画像を含むブロックの側の版で、入力モードごとに
  次のとおり（削除ファイルは全体が旧側のブロック）:

  | 入力モード | 新側のブロックの画像 | 旧側のブロックの画像 |
  |---|---|---|
  | worktree | 作業ツリーのファイル | `HEAD` |
  | staged | インデックス | `HEAD` |
  | コミット範囲（最終形） | `to` | `from` |
  | コミット範囲（コミットごと） | そのコミット | その親 |
  | manifest | レビュー対象の画像だけ | 同左 |
  | 復元 | 写しにある（レビュー対象の）画像だけ | 同左 |

  描画の時点で分かるもの（正規化した結果がリポジトリの外に出るパス、画像の拡張子で
  ないもの、manifest と復元でレビュー対象に一致しないもの）は `src` を出さず、alt
  テキストとパスを示す枠にする。レビュー対象の画像は、kemi がそのレビューで読んだ
  バイト列を配る（`R-SERVE`）。ファイルを読まないと分からないもの（symlink、上限を超えるもの、存在しない
  ファイル）は `src` を出し、エンドポイントが 404 を返したらページが同じ枠に差し替える。
- 外部 URL（`http:` / `https:`）の画像はブラウザがそのまま読む。プロキシは持たない
  （P20）。

変更の見せ方

- 描画するのは新側の文書で、旧側は消した範囲と、重ねられない書き換えの旧の範囲だけを
  描画して、新側の対応する位置に差し込む（削除ファイルは旧側の文書全体を描画する）。
  差分はソース表示と同じ行の整列から求め、ブロック（`CONTEXT.md`）に写す。
- ブロックの行レンジが行の整列の範囲に収まらないときは、その行を「対応する新の行が無く、
  変わっていない」として読む。全行がそうなった旧のブロックは、消したブロックとして
  差し込まない。
- 変更の無いブロックはそのまま出す。追加したブロックは追加色の左帯を付け、消した
  ブロックは元の位置に削除色の左帯で残す。
- 書き換えは、旧と新でブロックの種類と、中のインライン要素（リンク・強調・コードなど）
  の種類と順番が同じ「文のブロック」（段落・見出し・リスト項目）なら 1 つのブロックに
  重ね、消した語を削除色の取り消し線、足した語を追加色で示す。語の印は、旧のブロックと
  新のブロックのテキスト全体の語単位の差分から作る（行ごとの強調からは作らない）。
  リンクの `href` と画像の `src` はそのテキストに入らないので、URL だけが変わった
  ブロックは 1 つに重なるが語の印を持たない。
  それ以外（構造が違う文のブロック、コード塊、表の行）は、旧のブロックを削除色、
  新のブロックを追加色で上下に並べる。リストと引用は入れ物で、その中のブロックごとに
  上の規則を当てる。
- 追加だけのファイルは全ブロックが追加色、削除だけのファイルは全ブロックが削除色。
- すべてのブロックの要素（変更の無いものを含む）は `data-kemi-block` 属性を持つ。値の
  書式は契約で、`<side>:<start>-<end>`（`side` は `new` / `old`、行番号は 1 始まりで
  両端を含む。例 `new:12-15`、`old:3-3`）。重ねたブロックは新側のレンジを持つ。
  自動検査はこれを数える。
- 由来の行（`R-ORIGIN`）は描画表示では出さない。

表（CSV / TSV）

- 区切りは拡張子で決める（`.csv` は `,`、`.tsv` はタブ）。1 行が表の 1 行。`"` で囲んだ
  フィールドと、その中の `""` を解釈する。フィールド内の改行は解釈せず、`"` の対応が
  取れない行があるファイルは描画表示を出さない（P19。下の「上限と失敗」の経路）。
  列数が行ごとに違ってもそのまま出す。
- 1 行目は見出し行（`<th>`）。足した行・消した行・書き換えた行は Markdown と同じ色で、
  書き換えは旧の行を削除色、新の行を追加色で上下に並べる（セル単位の強調はしない）。

画像

- 画像として並べるのは、拡張子が画像で内容がバイナリと判定されたファイルと、拡張子が
  `.svg` のファイル。拡張子が画像でも内容がテキストのもの（Git LFS のポインタ、空
  ファイルなど）は今までどおりテキストの差分。manifest で `old` / `new` を文字列で
  与えた差分にも同じ判定をかける。入力モードは問わず、配るのは kemi がそのレビューで
  読んだバイト列（`R-SERVE`）。
- 表示できない画像（壊れたファイルなど。`<img>` の読み込みに失敗したもの）は、その側を
  バイト数だけの枠に差し替える。
  untracked の上限（`R-INPUT-3`、D6）を超えて内容を読まなかったファイルは、内容が
  無いので今までどおりバイト数の増減だけを示す。
- 旧と新を `<img>` で並べ、それぞれにバイト数を添える。追加と削除は片側だけを出す。
  改名だけでバイト列が同じときは 1 枚だけ出し、"unchanged" と添える。
- 片側が 5 MB を超えるときは、`R-VIEW` のバイナリと同じくバイト数の増減だけを示す。
  Markdown の相対パス画像の上限も同じ 5 MB。
- 画像のバイト列は token 配下のエンドポイントで配る（`R-SERVE`）。SVG は `<img>`
  経由でだけ出す（中のスクリプトを動かさない）。

コメント

- 描画表示のブロックにホバーすると `+` が出て、押すとそのブロックの元の行レンジへの
  行コメントになる（`R-COMMENT`。submit JSON は通常の行コメントと同じで、描画表示から
  付けたことは区別しない）。side は、新側にあるブロック（重ねたブロックを含む）は
  新側、消したブロックは旧側。複数ブロックの範囲選択は無い（P21）。
- 入力欄にはそのブロックの元の行を見せる。新側なら suggestion も書ける。
- 札と入力欄はブロックの直下に出す。既存のコメントは、その行レンジに重なる最初の
  ブロックの直下に出し、どのブロックにも重ならないもの（ブロック間の空行など）は
  直前のブロックの直下、直前のブロックが無ければ文書の先頭に出す。
- 画像へのコメントはファイル全体のコメントだけ（ファイルヘッダから）。

移動と帯

- `n` / `p` は、変更の印の付いたブロックとコメントの位置を止まる場所とする（`R-NAV`）。
  スクロールバー横の帯も同じ位置を写し、押すとそこへ移る。

上限と失敗

- Markdown と表で、片側が 10,000 行超または 1 MB 超のファイル（`R-VIEW` のハイライトと
  同じ境界）、描画に失敗したファイル、表の `"` の対応が取れないファイルは描画表示を
  出さない。画像にはこの境界は効かず、5 MB の規則だけが効く。
- 事前に分かるもの（行数・バイト数・表の `"` の対応）は、切り替えを無効にして理由を
  ツールチップに出す。切り替えを押してから描画に失敗したものは、ソース表示のままにして
  ファイルヘッダに理由を出す。どちらも理由の文言は契約としない。ソース表示は通常どおり。

ライブリロードと復元

- 更新バッジと読み込み直しは `R-LIVE` のまま。読み込み直しても、そのファイルの
  描画表示の状態は保つ。読み込み直しで描画できなくなったファイルはソース表示に戻し、
  切り替えを無効にする。コメントの `outdated` は `R-COMMENT` の規則のまま。
- 復元では写しの内容から描画する（`R-SESSION`）。

**成功条件**

- `<script>`、`<img onerror>`、`<iframe>`、`javascript:` のリンクを含む Markdown を
  描画した HTML に、それらが要素や属性として現れない（Rust のユニットテスト。生成した
  HTML 文字列を検査する）。
- インライン要素の種類と順番が変わらない、段落の 1 語の変更で、その段落のブロックが
  1 つだけあり、消した語と足した語の両方の印を持つ（純粋関数のテスト）。
- リンクを平文にした差分で、その段落が旧と新の 2 ブロックになる（純粋関数のテスト）。
- front matter 付きの Markdown で、先頭に無地の塊が 1 つ出て、その行レンジが front
  matter の行と一致する。閉じる `---` が無い Markdown では塊が出ない（純粋関数の
  テスト）。
- CRLF と複数バイト文字を含む Markdown でも、各ブロックの `data-kemi-block` の行レンジが
  元の行と一致する（純粋関数のテスト）。
- 表の分割で、`"a,b"` が 1 フィールド、`""` が `"`、タブ区切りが `.tsv` で効き、
  対応の取れない `"` を含む行があると描画不可になる（純粋関数のテスト）。
- 画像エンドポイントの応答に `Content-Security-Policy: sandbox` と
  `X-Content-Type-Options: nosniff` が付く（統合テスト）。
- `[x](../a.md)` の相対リンクを含む Markdown を描画した HTML に、そのリンクの `<a>` が
  無い（Rust のユニットテスト）。
- `../` でリポジトリの外に出るパスと画像でない拡張子を参照する Markdown を描画した
  HTML に、その画像の `src` が無く枠がある（Rust のユニットテスト）。
- `#` 始まりを参照する Markdown を描画した HTML で、リンクは `<a>` になり、画像は `src`
  の無い枠になる（Rust のユニットテスト）。
- symlink、5 MB 超、存在しないファイルを参照する Markdown を描画し、その `src` を
  取得すると 404 になる（統合テスト。URL は描画した HTML から取り、形には依存しない）。
- `src` の取得が 404 になった画像がページで枠になる（ブラウザ自動化）。
- フィクスチャの Markdown を描画表示にすると、`data-kemi-block` の数と行レンジが
  期待どおりになる（ブラウザ自動化）。
- 描画表示から付けたコメントが submit JSON に行コメントとして入り、`quote` がその
  ブロックの元の行になる（ブラウザ自動化）。
- 片側 10,001 行の Markdown で切り替えが無効になる（ブラウザ自動化）。
- 復元した Markdown を描画表示にでき、相対パス画像はレビュー対象のものだけ出て、他は
  枠になる（ブラウザ自動化）。
- 描画側のコメントの操作感（`+` の出方、札の位置、入力欄に元の行が見えること）
  は人が確認する。

**反例**

- Markdown の生 HTML がそのまま出て、リポジトリの内容がページでスクリプトを動かす。
- 構造の同じ段落の 1 語の変更で段落が旧と新の 2 つに割れる、または構造の違う段落を
  無理に重ねて読めない見た目になる。
- 描画表示から付けたコメントが submit JSON で別の形になり、エージェントが行を
  特定できない。
- 相対パス画像のエンドポイントがリポジトリの外のファイルを配る。
- 直接開いた SVG のスクリプトが kemi の API を呼べる。
- 起動時に全 Markdown を描画して、10,000 ファイルで 1 秒を超える。
- 10,000 行超の Markdown を描画して、ページが固まる。
- 復元で git を読みに行って、当時の差分と食い違う画像を出す。

## 作らないもの

- P15 `.rst` / AsciiDoc の描画。採用した描画器（ox-content）が対応していない。
- P16 GeoJSON など、`R-RENDER` に無いその他の形式の描画。優先度が低く、要るときは別の
  brainstorm で足す。
- P17 画像のスワイプと重ね合わせ（onion skin）。並べる比較だけ。
- P18 `.mdx`、front matter の中身、数式の解釈。front matter は無地の塊として出す
  （`R-RENDER`）。
- P19 表（CSV / TSV）のフィールド内の改行。対応の取れない行があるファイルは描画表示を
  出さない（`R-RENDER`）。
- P20 外部 URL の画像のプロキシ。ブラウザがそのまま読む。
- P21 描画表示での複数ブロックの範囲選択。範囲を選ぶときはソース表示で行う。

## 委譲

- D15 描画表示とソース表示を切り替えるキーの割り当て。既存のキー（`n` / `p` / `v`）と
  衝突しなければ、どのキーでも振る舞いは同じ。
- D16 描画結果のキャッシュ。持っても持たなくても画面は同じで、`R-SERVE` の「起動時に
  計算しない」を守る限り実装が決める。

## 却下

- R25 旧の描画と新の描画を 2 列に並べる（理由: 変更点を目で探すことになり、差分を読む
  道具として弱い）。
- R26 Markdown を開いたとき描画表示を既定にする（理由: GitHub と同じくソースが既定で、
  suggestion を書くにはソースが要る）。
- R27 Markdown の中の相対パス画像を出さない（理由: GitHub の rich diff に合わせ、
  スクリーンショット入りの文書を読めるようにする）。
