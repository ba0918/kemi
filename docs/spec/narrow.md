用語の定義は `CONTEXT.md`、成功条件と反例の書き方は [kemi 仕様](kemi.md) の冒頭にある。

## R-NARROW 狭い画面

ビューポートの幅が 720px 未満の状態を「狭い画面」と呼ぶ（`CONTEXT.md`。720px 以上は
「広い画面」）。LAN 公開（`R-SERVE` の `--bind`）でスマホから開いたときに、読めて
コメントして submit できるようにする。判定は幅だけで、端末の種類やタッチの有無では
変えない。この節は、幅 720px 未満に限って `R-VIEW` / `R-RENDER` / `R-COMMENT` の表示と
入口の規定を上書きする。上書きしないものは各節のまま。

**要件**

広い画面を変えない

- 幅で変わる規則は 1 つのメディアクエリ（`max-width` 719.98px 相当）に集め、JS も同じ
  メディアクエリを `matchMedia` で見る。幅の測り方はこれで CSS と JS で一致する。
- 狭い画面でだけ使う要素（ツリーを開く操作、「…」のメニュー、シートの閉じる操作、画面の下に
  浮かぶ「エージェントに渡す」（[agent-channel.md](agent-channel.md#r-agent-state-エージェントの状態)）、
  2 段目のバー）は常に DOM にあり、広い画面では CSS で隠す。広い画面で見えている要素と
  操作は変えず、`R-VIEW` の上部バーとヘッダの成功条件は広い画面でそのまま成り立つ。
- 幅がしきい値をまたいだら、再読込なしにその場で切り替わる。表示モードと折返しの切り替えは
  `R-VIEW` の「作り直し」の規則（上端に見えていた行を残す）に従う。開いていた引き出しと
  シートは閉じ、選択中の範囲と入力中の下書きは保つ。

配置

- ファイルツリーは隠し、上部バーの操作で左から重ねる引き出しとして開く。中身（グループ、
  ディレクトリ、状態、増減数、ノイズ、重要、コメント件数、見た）は `R-VIEW` のまま。
  ファイルを選ぶか、引き出しの外を押すと閉じる。引き出しが閉じるのは表示するファイルを
  選び直すときすべてで、`n` / `p` でのファイル移動、更新バッジの読み込み直し、テーマや
  構文ハイライトの切り替えを含む。本文は全幅。
- 表示モードは常に 1 列。2 列への切り替えは出さない。広い画面に戻ると、覚えている
  表示モード（`R-VIEW`）に戻る。描画表示の画像は 1 列の規則で上下に並ぶ（`R-RENDER`）。
- 折返しの既定はオン。狭い画面での切り替えはページを開いている間だけ覚え、localStorage
  には入れない（`R-SERVE` の localStorage の用途は変えない）。広い画面の既定（`R-VIEW`）は
  変えない。
- 上部バーは 2 段。1 段目は `kemi` の名前、`title`、ツリーを開く操作、コメント件数付きの
  会話パネルの開閉、更新バッジ、「…」のメニューを開く操作（`--live` では見方のタブも。
  [live.md](live.md#r-page-view-ページの見方)）。2 段目は、コミット範囲ではグループ単位の切り替え
  （`R-UNIT`）を左に、見たの進捗（`R-SEEN`）、承認と変更要求のボタン（`R-SUBMIT`）。
  表示の操作（折返し・重要のみ・変更量順・テーマ）は「…」の 1 つのメニューにまとめ、
  メニューの中では `R-VIEW` の並びで文字ラベルを付けて出す（メニューは小さな覆いで、
  シートにはしない）。メニューは項目を押しても開いたままで、続けていくつも切り替え
  られる。閉じるのはメニューの外を押したときと、幅をまたいだとき。2 段目が入りきらないときは、見たの進捗を数字だけにし、それでも
  入らなければ 3 段目に折り返す。送信ボタンとグループ単位の切り替えの文言は変えない。
  `subtitle` と `meta` は `title` を押すと開くシートに入れる（広い画面では `R-VIEW` の
  とおり上部に出る）。
- ファイルヘッダは追従し、1 行目はパス（収まらなければ先頭を省略記号で切り、末尾を
  見せる）、残りにヘッダの操作と印（`R-VIEW`。描画表示の切り替えを含む。長い note では
  折り返して行が増えてよい）。
- 会話パネルは画面いっぱいのシート（閉じる操作つき）で出す。中身は同じ。狭い画面で
  ページを開いたときは、覚えている開閉（`R-VIEW`）にかかわらずシートを閉じた状態で始める。
- 札とコメントの入力欄は、本文の幅いっぱいから始める（行の位置からのインデントを
  付けない）。入力欄の約 72 文字の上限（`R-VIEW`）はそのまま。
- 「…」のメニューの「Comments」の切り替えで、札を隠して本文だけにでき、切り替えは
  ページを開いている間だけ覚える。隠している間もコメントの有無は行番号の欄のコメント色の
  線（`R-VIEW`）と上部バーの件数で分かる。札を押すと、会話パネルのシートでそのスレッドを
  開く。シートで開いたスレッドからその行へ移ると、シートを閉じてその行を見せる。
- 変更間の移動の操作と帯（`R-NAV`）、由来の行（`R-ORIGIN`）、見たのチェック（`R-SEEN`）は
  変えない。キー操作も変えないが、表示モードのキー（`u` / `s`）は狭い画面では効かず、
  移動の操作のキーの表示は出さない（操作は同じ）。`n` / `p` でファイルをまたいでも
  引き出しは開かず、引き出しの中の開閉だけを `R-NAV` のとおり行う。

コメントの入口

- 行番号のタップで選ぶ。選択が無いとき、タップした行が 1 行の選択になり、その行に `+` が
  出る（ホバーを要しない）。選択があるとき、同じ側で表示中の連続した行の中の別の行番号を
  タップすると、その 2 行を両端とする範囲になり、`+` は範囲の最後の行に移る。それ以外の
  タップ（反対側の行番号、折りたたみをまたぐ行、3 つ目以降の行）は、その行を両端とする
  新しい 1 行の選択に置き換える。1 行の選択でその行を再タップすることと、本文の中で
  行番号以外を押すことは選択を解除する（上部バーやファイルヘッダを押しても解除しない）。
  範囲の選択では解除にならず、その端の行の再タップも新しい 1 行の選択になる。`+` を押すと
  `R-COMMENT` の入力欄が開き、入力欄が開いている間は解除せず、入力を取り消すと選択も
  解除する。範囲は左右
  どちらか片側の連続した行で、`R-COMMENT` の規則のまま。
- 狭い画面では、行番号の押し下げとホバーによる選択（広い画面のドラッグ）は働かない。
- 描画表示（`R-RENDER`）のブロックはタップで `+` が出る。
- 広い画面のホバーとドラッグ（`R-VIEW`）は変えない。

**成功条件**

- 幅 390px で開くと、ツリーが見えず、上部バーの操作で引き出しが開き、ファイルを選ぶと
  閉じてそのファイルが出る（ブラウザ自動化。ビューポートの幅を指定して開く）。
- 幅 390px で、2 列への切り替えが無く、行が折り返され、行番号のタップで `+` が出て、
  2 つ目のタップで範囲になり、付けたコメントが submit の JSON に行コメントとして入る
  （ブラウザ自動化）。
- 幅 390px で、コメントを付けると札で出て、「…」の「Comments」で札が消えて行番号の欄の
  色の線は残り、札を押すと会話パネルのシートでそのスレッドが開く（ブラウザ自動化）。
- 幅 1280px で開いたとき、`R-VIEW` の上部バーとヘッダの成功条件がそのまま成り立ち、
  狭い画面でだけ使う要素が見えない（ブラウザ自動化）。
- 幅を 1280px から 390px に変えると再読込なしに狭い画面の配置になり、戻すと元に戻る
  （ブラウザ自動化）。
- 幅で変わる規則が 1 つのメディアクエリ（CSS と `matchMedia`）に集まっている（差分の
  レビューで確かめる）。
- 実機のスマホで LAN 公開のページを開き、読む・コメントする・submit するまでできる
  （人による確認）。

**反例**

- 広い画面のどこかの見た目や操作が変わる。
- 狭い画面でツリーが本文を押しつぶす、または 2 列表示が選べて読めない。
- 行番号をタップしても `+` が出ない。
- 幅をまたぐたびに再読込が要る。

## 作らないもの

- P22 スワイプなどのジェスチャ操作。
- P23 PWA とオフライン動作。
- P24 UA 判定による別ページやリダイレクト。狭い画面は幅だけで決める（`R-NARROW`）。
- P25 ピンチズームの禁止。viewport の設定は今のまま拡大できる。
- P26 狭い画面専用の設定項目。
