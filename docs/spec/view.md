# kemi 仕様: 差分の表示

[kemi 仕様](kemi.md) の一部。差分の表示（ファイルツリー、本文、テーマ、ハイライト、横スクロール）。
用語の定義は `CONTEXT.md`、成功条件と反例の書き方は [kemi 仕様](kemi.md) の冒頭にある。

---

## R-VIEW 差分の表示

説明の入口と見方の切り替えは [R-EXPLANATION-VIEW](explanation.md#r-explanation-view-入口と移動) を適用する。

見た目は diffs.com（OSS ライブラリ `@pierre/diffs`、Apache-2.0）を参照するが、
コードはコピーしない。

**要件**

- 1 列（unified）と 2 列（split）を切り替えられる。行番号、変更記号、単語単位の
  強調、ハンクの折りたたみと展開（クリックでその場に開く）を持つ。
- 1 列表示では、連続する書き換えを「消した行の塊 → 足した行の塊」の順に並べる。
  旧と新を 1 行ずつ交互に並べない。単語単位の強調は、対応する旧と新の行の組で保つ。
- 2 列表示では、書き換え行の旧側を削除の色、新側を追加の色で塗り、変更箇所の強調も
  旧側は削除の強調色、新側は追加の強調色にする。相手の無い側（追加だけ・削除だけの
  行の空いた側）は追加・削除の色を付けず、斜線の無地にする。
- 行番号の欄にも、その行の追加・削除の色を付け、変更記号（`+` / `−`）を太くする。
- 折りたたみ行には、隠れている行数を示す展開の操作と、その下に続く表示範囲の旧・新の
  行番号（git の `@@` と同じ意味）を出す。囲みの文脈（関数名など）は出さない
  （`P11`）。
- 最終形では、各変更ブロックのすぐ上に 1 行の「由来の行」を出す（1 列でも 2 列でも）。
  中身は `R-ORIGIN` の由来。由来を計算している間は行だけ先に出して計算中の印を置き、
  後から行が増えて表示がずれないようにする。由来が既定で無効のファイル（`R-ORIGIN`
  の上限を超えるもの）では由来の行を出さず、有効にすると出す。最終形以外では出さない。
- ファイルヘッダは追従（sticky）し、左のファイルツリーから各ファイルへ飛べる。
  狭い画面（`R-NARROW`）ではツリーは引き出しになる。
- ファイルを選ぶと、ファイルヘッダは内容の取得を待たずに選んだファイルへ切り替わる。
  取得が終わるまで、ヘッダの操作（見た・コメント・展開・ハイライト・描画表示の切り替え）は無効にする。
- 構文ハイライトをサーバ側で行う。左右それぞれのファイル内容を行単位で着色し、
  複数行にまたがる文字列・コメントを壊さない。
- 1 ファイルの片側が 10,000 行超または 1 MB 超のときはハイライトを切って表示し、
  そのファイルでだけ有効化できる。
- 折返しは既定で無効（横スクロール。狭い画面は `R-NARROW`）。有効にした場合も行の高さを実測して
  描画を破綻させない。2 列表示の横操作は `R-VIEW-HSCROLL` に従う。
- 表示する行を作り直す操作（折りたたみの展開と畳み直し、表示モードと折返しの
  切り替え、由来の出し入れ、テーマとハイライトの変更）でも、上端に見えていた行はその
  位置に残す。取得した行をそのまま並べ直す作り直し（折りたたみの展開と畳み直し、
  表示モードの切り替え、由来の出し入れ）では、同じファイルで測った行の高さを引き継ぐ。
  折返しの切り替えと、行を取り直すテーマやハイライトの変更では、高さを測り直す。
- 表示中の行だけを DOM に載せる。1 ファイル 50 万行でもスクロールが固まらない。
  行要素は `data-kemi-row` 属性を持ち、自動検査が数えられる。描画表示（`R-RENDER`）は
  行を持たず、上限の範囲で文書全体を載せる。
- ノイズ（`CONTEXT.md` 参照）に分類したファイルは既定で畳んで表示し、開ける。
  分類は 1 つの分類器で行い、規則（パスパターン、`.gitattributes` の
  `linguist-generated`、バイナリ判定）は実装に委譲する（D6）。
- 増減数で並べ替えるトグルを持つ。既定の並びは入力の順で、トグルを操作した時だけ
  並びが変わる。入力の順は、manifest は配列の順、コミットごとはコミットの古い順、
  最終形・worktree・staged のファイルは git の差分の出力順（パスの順）。
- ページ上部に `title` / `subtitle` / `meta` を表示し、表示モード・折返し・
  重要のみ・変更量順・テーマの操作を、文字ラベルを出さないモノクロのアイコンと
  ツールチップでまとめる。例外として、コミット範囲ではグループ単位の切り替えを
  "Final state | Per commit" の文字付き 2 択でタイトルの右に置く（`R-UNIT`）。
  上部にはほかに、見たの進捗（`R-SEEN`）、コメント件数付きの会話パネルの開閉、
  更新バッジ（`R-LIVE`）、承認と変更要求のボタン（`R-SUBMIT`）を置く。左上の名前は
  `kemi` の文字にする。`--live` のレビューでは、名前の右にページの見方とコードの見方を
  切り替えるタブを置き、ページの見方の間の上部バーは [live.md](live.md#r-page-mode-起動) に従う
  （コードの見方の上部バーはこの節のまま）。
- 本文側のグループ帯（表示中のファイルが属するグループの見出し）には `title` を
  表示する。`why`（説明）は既定で畳み、開ける。開閉の状態はページを開いている間
  だけ覚える。`watch`（見てほしい点）は畳まずに常に表示する。ツリーのグループ
  見出しには `title`、見たの進捗（`R-SEEN`）を出し、`why` と `watch` は出さない。
- コミットごとの単位で、件名が「英小文字の種類、続いて任意の `(scope)`、任意の `!`、
  最後に `:` と空白」で始まるとき（例 `feat: `、`fix(ui)!: `）、`:` の前までを色の無い
  小さな枠で示し、件名からは外す。対象はツリーのグループ見出しと本文側のグループ帯
  だけで、会話パネルと由来は件名をそのまま出す。submit JSON の `group_title` は
  件名のまま変えない。
- ファイルヘッダに、パスのコピーと全行展開の操作と、そのファイルのコメント件数
  （ファイル全体へのコメントを含む）を持つ。Markdown と表と SVG のファイル（`R-RENDER`）では、
  描画表示とソース表示の切り替えも持つ（SVG 以外の画像は持たない）。
- コメントの入口は行にホバーすると出る `+` とし、行番号のドラッグでレンジを
  選べる（狭い画面では `R-NARROW` のタップ）。ファイル全体へのコメントはファイルヘッダから入れる。suggestion は
  コメント入力の一部として置換後のテキストを書き、コメントに添えて表示する。
  適用はエージェントが行うことを画面に示す。コメントは差分の中に必ず札で出し、会話パネル
  だけに出すことはしない。
- 行コメントは、対象範囲の最後の行の直下に、コードの列の位置から始まる 1 行の札で
  表示する。札は対象の行を指し、範囲の行には行番号の欄の左端にコメントの色の
  線を付ける。札は本文の 1 行目と返信の数を示し、そのスレッドを最後に開いた後に
  届いたエージェントの返信があれば新着の印を付ける。1 行目が収まらないときは省略記号で
  切る。作成者の札（「あなた」）は出さない。ファイル全体へのコメントはファイルヘッダの
  下に同じ札で出す。
- 札を押すと、会話パネルでそのスレッドを開く（畳んでいれば開く）。開いたスレッドは
  本文・suggestion・返信のすべてと対象の行の前後を見せ、返信・解決・編集・削除の操作を
  持つ。差分の中で本文を広げる吹き出しは持たない。コメントの入力欄（新しく書く・
  編集する）は差分の中に出し、入力欄の表示幅は約 72 文字に制限して超える行は折り返す
  （入力の文字数は制限しない）。
- 会話パネルは画面の右に高さいっぱいで置き、発言（[agent-channel.md](agent-channel.md)）と
  すべてのグループ単位のスレッドを、最後に書き込みがあった順（`R-SESSION` の通し番号）に
  1 本に並べる。返信が書かれたスレッドは並びの一番下へ移る。すべて・未解決・表示中の
  ファイルで絞り込める。スレッドの項目はグループ単位、パス、行範囲、最後の書き込みを示し
  （コミットごとの項目はそのコミットの件名も示す）、押すとパネル全体がそのスレッドになる。
  開いたスレッドからは、その単位へ切り替えてその行へ移れる。履歴の書き換えで消えたグループの
  コメント（`R-LIVE`）は「消えたコミット」として示し、開いても移る操作は出さない。
- 会話パネルは既定で畳んだ細い帯で始め、帯には新着の数を出す。新着の数は、新着の印が
  付いたスレッドの数と、パネルを畳んでいる間に届いたエージェントの発言の数の合計。どこまで
  見たかは保存せず、ページを読み込んだ時点であったものは新着にしない。返信や発言が届いても
  勝手には開かない。幅は縁を掴んで変えられる。開閉と幅は表示の好みとして覚える
  （`R-SERVE`）。
- 左のツリーはグループとディレクトリを開閉でき、ファイルとディレクトリを
  テーマ色に追従するモノクロの SVG アイコンで区別する。
- ファイルツリーにはパス、状態、増減数、ノイズかどうか、重要かどうか、コメントの
  件数、見たかどうか（`R-SEEN`）を示す。状態は 1 文字（`A` 追加 / `D` 削除 /
  `R` 改名 / `M` 変更）で示し、`M` は目立たせない。
- 本文の基準サイズは 15.5px とし、余白もそれに比例させる。
- 配色は意味ごとの役割に分ける: 進捗・見た・主な操作は藍系、コメントは付箋の黄系、
  重要と見てほしい点は藤（紫）系、追加は緑系、削除は赤系。追加と削除以外の役割に
  赤系の色を使わない。各テーマでの具体的な色の値は D2。
- 見た目の参照は `docs/design/ui-mock-v2.html`（採用したモック）に置く。モックと
  この仕様が食い違うときは仕様が正しい。
- テーマは light / dark の自動と手動切替、および数種のプリセットを持つ。
  配色は CSS 変数に閉じる。
- バイナリは内容を出さず、バイト数の増減だけを示す。例外は `R-RENDER` の画像で、
  上限の範囲で旧と新の画像を並べる。
- CRLF と LF の違いは表示時に正規化し、改行コードの変更のみを差分として
  強調しない。最終行の改行の有無は表示しない。
- `approval` は画面に出さない。`identity`（承認対象を識別する値。manifest が与える）は
  人が照合できる値ではなく、エージェントが承認後にコミットするバイト列と突き合わせる
  ための記録なので、結果の JSON にそのまま返すだけにする（`R-RESULT`）。

**成功条件**

- 50 万行のフィクスチャファイルを開いてスクロールしても操作が固まらない
  （人が確認）。併せて、DOM 上の `data-kemi-row` 要素数が表示中の行数程度に
  収まる（ブラウザ自動化で確認）。
- 10,000 行超のファイルでハイライトが切れ、当該ファイルで有効化できる。
- `Cargo.lock` などの lockfile が既定で畳まれ、開ける。
- 広い画面（`R-NARROW`）で、ヘッダに `subtitle` と `meta` が出る。
- グループ見出しに `watch` が常に出て、`why` は畳まれた状態から開ける。
- 1 列表示で、連続する 3 行の書き換えが旧 3 行、新 3 行の順に並ぶ（表示行を作る
  純粋関数のテスト）。
- 測った行の高さと上端の行を、作り直しの前後で対応づける純粋関数のテストで、
  上に隠れた開いたコメントの高さが折りたたみの展開後も残り、消えた行の高さは残らず、
  上端の行が展開や由来の追加の後も見つかる。画面では、上に隠れた開いたコメントが
  ある状態で下の折りたたみを展開しても、上端に見えている行が変わらない（人が確認）。
- 2 列表示で、書き換え行の旧側に削除の色、新側に追加の色が付き、相手の無い側に
  追加・削除の色が付かない（人が確認）。
- ファイルを切り替えた直後、取得が終わる前に見たを押しても、前のファイルに
  見たが付かない（ブラウザ自動化で確認）。
- 複数行のコメントが範囲の最後の行の直下に出る（配置を決める純粋関数のテスト）。
- 既存のコメントが 1 行の札で出て、押すと会話パネルでそのスレッドが開き、本文がすべて
  見える（人が確認）。
- 会話パネルで開いたスレッドから、そのコメントの行へグループ単位をまたいで移れる（人が確認）。
- ツリーのグループとディレクトリが開閉できる。
- ファイルヘッダのパスコピーと全行展開が動く。
- 行の `+` からコメントを追加でき、その行の直下に表示される。
- 会話パネルを畳んでいても、コメントは差分の中の札で見える。広い画面（`R-NARROW`）で、上部バーの表示の操作
  （表示モード・折返し・重要のみ・変更量順・テーマ）は文字ラベルを持たない。文字ラベルを持つ上部バーの
  操作は、グループ単位の切り替え、送信のボタン、更新バッジ、コメント件数付きの
  会話パネルの開閉だけである（title / subtitle / meta、`kemi` の名前、見たの
  進捗は操作ではないので、この条件の対象外。`--live` の見方を切り替えるタブも対象外で、
  ページの見方の上部バーは [live.md](live.md#r-page-mode-起動) の成功条件で確かめる）。
- 「見た」と折りたたみの状態が再読込後も残る。コメントはセッションが残る限り残り、
  保留と復元をまたいで続く（`R-SESSION`）。

**反例**

- 50 万行すべてを行要素として生成する。
- ハイライトが 1 ファイルの全行を起動時に処理する。
- 改行コードだけの変更が、全行の変更として表示される。
- lockfile が通常ファイルとして展開される。
- ノイズ判定が 2 箇所にあり、ツリーと本文で結果が食い違う。
- コメントが会話パネルにしか出ず、差分の中に札が無い。
- 送信の確認をキャンセルしてもレビューが終了する。
- 1 列表示で、書き換えの旧と新が 1 行ずつ交互に並ぶ。
- 2 列表示で、書き換え行に色が付かない、または旧側の変更箇所が追加の色になる。
- 取得中にヘッダの見たを押すと、前に表示していたファイルに見たが付く。
- 範囲コメントが範囲の途中に割り込み、範囲の行が上下に分かれる。

### R-VIEW-HSCROLL 2 列表示の同期横スクロール

長い行の続きがあると分かり、折り返さずに旧・新の同じ横位置を比較できるようにする。
対象は 2 列表示のみ。1 列表示は既存の横スクロールを維持する。

**要件**

- 折返しが無効で、実測済みのコードに表示幅を超えるものがある場合、差分表示領域の
  下端に横スクロールバーを 1 本設ける。ファイルの末尾まで縦に移動しなくても操作できる。
  行ごと・左右別々のスクロールバーは設けない。
- バーの操作で、表示中の全行の旧・新のコードを同じ画素数だけ横に動かす。
  短い行や相手の無い側も同じ横位置を使い、コードが尽きた部分は空白とする。
  コードは各ペイン内に収め、隣のペインに重ねない。
- 行番号、変更記号、中央の境界、コメントと入力欄、由来の行と理由、折りたたみの
  操作は横に動かさない。横操作で縦位置や行の高さを変えない。
- バーだけでなく、コード欄に対する横スクロール入力も共通の横位置を動かす。
  バーはマウスで操作でき、キーボードでもフォーカスして操作できる。
  バーを意図的に非表示にしない。OS・ブラウザによる自動非表示はその設定に従う。
- 横幅は表示したコードを実測して決める。幅計測のために全行を画面要素として
  生成しない。左右で最大の実測幅を共通の幅として記録する。
  まだ表示していない長い行の幅は、その行が表示されたときに初めて反映してよい。
- 同じファイルエントリを表示している間、縦移動、折りたたみの開閉、表示モードや
  折返しの切り替え、画面のリサイズでは記録した最大幅を縮めない。
  さらに長い行を表示したら最大幅とバーの移動範囲を広げ、現在の横位置は変えない。
  記録した最大幅がペインに収まる場合はバーを隠す。
- 横位置と最大幅は現在のファイルエントリを開いている間だけメモリに持つ。
  別のファイルエントリを選んだら両方をリセットする。元のファイルへ戻った場合も
  左端から始める。ページ再読込を越えて保存しない。
- 折返しを有効にすると、バーを隠し、コードの横移動を解除して折り返す。
  2 列表示の横位置は覚えておき、折返しを無効にしたら復元する。
  1 列表示へ移った間も 2 列表示の横位置を保持し、2 列表示に戻ったら復元する。
- 同じファイルエントリの内容更新、テーマ変更、ハイライトの切り替えでは、最大幅を
  捨てて表示中のコードから測り直す。横位置は可能な範囲で保つ。
  幅の測り直し・画面のリサイズ・横位置の復元で、横位置が移動可能範囲を超える場合は
  その末端に補正する。移動範囲が無い場合は左端に補正する。

**成功条件**

- 長さが異なる旧・新の行を 2 列・折返し無効で開き、下端のバーを操作すると、
  両側のコードが同量動き、各行の末尾まで読める。行番号・コメント・中央の境界は
  動かず、文字が隣のペインに重ならない（ブラウザ自動化と人の操作で確認）。
- 右へ移動した状態で縦スクロールやコメントの開閉をしても、作り直された行が
  同じ横位置で表示される（ブラウザ自動化で確認）。
- 短い行だけの場所へ縦移動してもバーの範囲が縮まず、未表示だった長い行が
  現れた場合だけ広がる。範囲が広がっても読んでいた横位置は変わらない。
- Wrap の ON→OFF、2 列→1 列→2 列で横位置が復元される。内容更新・テーマ変更・
  ハイライト切り替えでは再計測され、復元不能な横位置だけが末端に補正される。
- 別のファイルへ移ると左端から始まり、前のファイルの最大幅が残らない。
  幅の計測を含めても `R-VIEW` の 50 万行の操作性と行要素数の条件を満たす。

**反例**

- 長い行が見切れるが、横操作の入口が無く Wrap を有効にするしかない。
- 右へ移動しても短い行は左端のままで、旧・新の対応する横位置がずれる。
- 縦スクロールやコメント操作のたびに横位置が左端へ戻る。
- 長い行が画面外へ出るとバーの範囲が縮み、横位置が勝手に戻る。
- 折返し中もコードが横へずれたまま、またはコメントまで横へ動く。
