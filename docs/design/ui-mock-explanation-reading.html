    エージェントの説明版 1 · 10/11 20:48

    大量の差分を、目的と前提から読めるようにする

    Explanation・Code・Page の会話を共通にし、図付きの補足と、説明から差分へ移っても戻れる仕組みを足した。承認の対象は説明ではなく、manifest に挙げた実装ファイルの正確なバイト。

    読む順は説明者の提案。git のコミット単位とは一致しない。

    01

    目的とレビュー状況

    何が変わり、何を承認するのか。

    LLM に任せて実装を進めると、差分の量に人間の理解が追いつかない。1 ファイルずつ差分を読むと時間がかかりすぎるし、全体を把握するのは現実的ではない。

    この機能は、エージェントが全体の説明、前提、個別の説明をある程度の粒度で書き、レビューする人がそこへ質問できるようにする。必要なら図や疑似コードも使う。

    • 説明は Explanation タブに出る。差分は今までどおり Code タブで見る。
    • 説明のどこにでもコメントでき、エージェントは説明の更新か返信で答える。
    • 説明が更新されても、前の版に付けたコメントの引用は失わない。
    確認してほしい点

    承認の対象は説明ではなく実装ファイルのバイト。説明だけを直しても、承認はやり直しにならない。この読みで困る場面はあるか。

    変更前と変更後

    変更前差分を左のファイル一覧から 1 件ずつ開く。変更の意図はコミットメッセージから推測するしかない。
    変更後Explanation で意図と前提を読み、参照から該当の差分へ飛ぶ。戻ると読んでいた場所に戻る。
    02

    元の説明・引用を失わない

    説明が更新されても、質問した時点の文面が読める。

    説明と差分は別々に版を持つ。説明を更新すると版の番号が上がり、画面には新しい版が届いたことだけを知らせる。読んでいる途中で本文が勝手に差し替わることはない。

    コメントは作った時点の版とブロック ID を覚える。同じ ID・同じ内容のブロックが新しい版にもあれば、そのブロックのそばにもコメントを出す。内容が変わったブロックのコメントは古い版の引用付きで会話パネルに残る。

    説明の版が上がる流れ

    03

    説明から差分へ移っても読む場所を保つ

    参照で Code へ飛び、戻ると同じ段落に戻る。

    参照ボタンを押すと Code タブの該当行へ移る。Explanation のタブには戻る印が付き、押すと移る前に読んでいた段落の位置へ戻る。

    差分の上に「説明へ戻る」の行は足さない。差分の表示領域を削ると読みにくくなるため、戻る操作はタブの切り替えに統合した。

    戻り先の覚え方

    // 参照へ移る直前に、読んでいた位置を覚える
function followReference(reference) {
  state.explanationReturn = {
    revision: state.explanation.revision,
    blockId: topVisibleBlock(),
  };
  selectView("code");
  showLines(reference.path, reference.lines);
}
    04

    図と文章を同じ境界で安全に読む

    エージェントの書いた図や文章でページを壊させない。

    図は shoryo と同じ描画を使い、sequence と flow は折り返しても情報を落とさない。図の中の文字はすべてテキストとして描き、HTML をそのまま差し込むことはしない。

    本文の Markdown は許可した要素だけを描く。リンクは http(s) と、差分への参照だけを受け付ける。

    確認してほしい点

    表と画像は今回の対象外にした。説明に表が欲しくなる場面がどれくらいあるか。

    05

    公開契約と検証

    CLI と JSON の形、テストで固めたこと。

    kemi explain <id> --file で説明を丸ごと差し替える。差し替えは原子的で、途中で失敗したら前の版のまま残る。

    • 説明の JSON は版・節・ブロックの 3 層。ブロック ID は作成者が決める。
    • 返信は kemi reply の型付きの書き込みで送る。図も返信に入れられる。
    • ブラウザの検査は light / dark と幅 390px で回している。
