01 / WORKFLOW

Read. Ask.
Then decide.

A place to think and communicate,
between terminal and browser.

  1. 01↗

    Read the explanation

    With an agent, start with an Explanation: what changed, why, and what needs your judgment. Follow its links to the code. You can also open a diff directly.

    kemi --from main --explanation why.json
  2. 02＋

    Ask before deciding

    Comment on the explanation or a line. Press Hand to agent to send your feedback after the agent connects with kemi wait. Replies appear in Conversation; the review stays open.

    Explanation + Conversation
  3. 03↵

    Return your decision

    Press Approve or Request changes when you are ready. Your decision, comments, suggestions, and conversation return to the starting terminal as one JSON document.

    Standard output → agent

02 / MADE FOR READING

Give the change
your attention.

The views you need, close at hand.
The judgment stays with you.

−＋
Understand the reason. Inspect the code.
Read and comment on an Explanation before the diff. Follow its Code links, then switch a commit range between final form and per-commit views to inspect the history.
Read documents. Review a running page.
Markdown, CSV / TSV, and images have rendered views. With kemi --live, inspect a local running page at different widths, compare snapshots, and comment with Element, Arrow, or Pen.
Read locally. Return suggestions.
kemi listens on loopback by default. It never edits your files; suggested changes are returned as JSON.
03 / GET STARTED

Try kemi on
your next change.

The name comes from the Japanese “kemi suru”: to review.
Start by opening a diff in your own repository.

macOS · Linux · Windows ／ x86_64 & arm64

Install from a ZIP on Windows

Download kemi-<target>.zip for your CPU from the latest GitHub Release. Extract kemi.exe and add it to your PATH. Git must also be on your PATH.
